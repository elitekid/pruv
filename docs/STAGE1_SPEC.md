# 1단계 설계: 정제 타입·불변식 자동 추론

> 상태: **확정**(2026-11-11). 초안은 설계 위임(Codex gpt-6-astra), 설계 논쟁 1회(같은 모델, 반대 입장) 뒤 메인이 확정했다. 반영 내역은 문서 끝 "설계 논쟁 반영 기록". 아래 0절이 본문보다 우선한다.

## 0. 확정 결정 요약(본문보다 우선)

1. **세 묶음으로 나눈다.** A 정제 타입 → B 템플릿 기반 Houdini 추론(구간 분석 없음) → C 구간 분석(B의 템플릿만 기준선 대비 효과를 측정한 뒤 착수 여부 결정). 1단계 첫 완료 범위는 A다.
2. **묶음마다 Python 구현 → 대응 Rust 구현 → AST·오류·SMT·출력 대조(`tests/m3_all.py` 확장)를 한 묶음 안에서 끝낸다.** P/R은 묶음 안의 구현 순서이지 따로 통합하는 묶음이 아니다(README 새 기능 정책과 같음).
3. **문법:** 값 범위는 닫힌 `L..=U`, 길이 상한은 `; <=N`. 기존 `forall/exists`·집계의 `lo..hi`(상한 제외)와 표기로 구별한다. 예: `a: [i64 | -1_000_000_000..=1_000_000_000; <=1_000_000]`, `x: i64 | 0..=100`. 경계는 부호 있는 십진 정수 리터럴만(부호 적용 뒤 i64 검사, `-9223372036854775808` 허용), `1e9`는 `parse/refinement_syntax`로 거부하고 십진 표기를 안내한다.
4. **미지원 위치**(필드·payload·Option/Result 내부)는 `parse/refinement_position`으로 거부한다. 미지원 정제를 보존하는 타입 표현은 만들지 않는다.
5. **추론(B)은 첫 판에서 명시적 켜기 옵션 `--infer`**로 낸다(기본 꺼짐). 예산 수치(64·512·rlimit 100,000·500ms·5초)는 측정용 시작값이다. 기본 켜기는 측정 뒤 다시 정한다. `--show-inferred`는 B에 포함.
6. **회차 상태 격리:** Houdini 각 회차는 고정 후보 맵으로 함수 전체를 새 기호 상태에서 실행하고, 이전 회차의 경로 조건·`seen`·오류·판정·집계 캐시·보조정리를 쓰지 않는다. 후보는 도달하는 모든 진입·back-edge 경로에서 정의역과 값 의무가 성공할 때만 남는다. 탐색 질의는 `proved / not_proved / resource_unknown / timeout / error`를 명시적으로 돌려주며, 기존 `prove()`의 오류 기록·반환값으로 판정하지 않는다. 보조정리 없는 첫 시도의 `sat`만으로 제거하지 않고 허용된 재시도까지 본다. 시간 초과는 후보 제거로 바꾸지 않는다(`verify/inference_timeout`).
7. **배치·정의역:** 불변식 순서는 필수 정제 → 사용자 원래 순서 → 자동 고정 순서. 한 절의 정의역을 검사할 때 그 절이나 뒤 절의 현재 상태 값을 가정하지 않는다(보존 검사의 이전 반복 머리 귀납 가정은 사용). 자동 후보는 자체 가드나 앞선 고정 순서의 후보로 정의역을 증명해야 한다(`max/min` 은 자체 가드로 빈 범위를 막고, sum/count 접두 구간의 배열 범위는 앞선 경계 후보에 기댄다).
8. **이름·선언 결합:** 정제 주석은 선언 ID와 원본 위치를 가진다. 합성 한정자 이름은 사용자 이름과 충돌하지 않고(포획 없는 치환), 합성 계약도 기본 타입·스코프 검사를 거친다. 필수 불변식은 그 루프 머리에서 살아 있는 선언에만 만든다. 지역 선언·재대입·원소 저장 의무는 그 연산 지점에서 검사하며 뒤에서 바로 `return`해도 생략하지 않는다.
9. **havoc:** 첫 판은 기존 havoc(변경 배열의 내용과 길이를 모두 새로 만듦)을 유지한다. 길이 별칭(`n = len(a)`)·옛 원소 범위를 havoc 뒤에 직접 가정하지 않고, 유지할 관계는 필수 불변식 의무나 후보로 증명한다. 전체 재대입은 옛 요약을 무효화한다.
10. **모드 축:** 증명 여부와 `--trust-callers`는 독립된 두 축이다. 증명 모드는 정제의 정적 의무를 모두 검사한다. 안전 모드는 지역·반환 정제를 보장하지 않는다. 매개변수 정제의 실행 검사(공개 경계, 안전 모드 내부 호출)는 `--trust-callers`가 없을 때만 한다. 반복 예산은 함수 진입 한 번당 하나(합성+사용자 requires 공유). 반환·지역 정제용 실행 검사는 더하지 않는다. 문서·오류 안내에서 정제를 실행 강제 타입처럼 설명하지 않는다.
11. **질의 기록 경계:** 탐색과 최종 검증의 모든 solver 호출은 공통 실행·기록 경계를 지난다. 실제 timeout·rlimit·seed, 재시도 여부, `reason_unknown`, 단계·회차·후보·의무 ID를 기록하고, 별도 모듈의 solver도 빠짐없이 기록한다. `--no-infer`(기본) 경로의 기존 모델 생성 횟수·SMT 이름은 바뀌지 않는다.
12. **재현성 범위:** 후보 생성 순서와 질의 구성은 결정적이다. solver 판정과 채택 후보의 일치는 지정한 solver 프로필(z3 버전·빌드·플랫폼·옵션·추론 설정 버전)에서만 시험하고, 다른 버전 사이의 같은 판정은 보장하지 않는다.
13. **대조기:** "두 판 결과가 같음"과 "검증 완료"를 따로 센다. 같은 추론 timeout·미결은 성공 표본이 아니다. 재시도로 해소된 차이도 첫 결과를 남긴다. 새 증명 옵션이 어댑터와 Rust dump에 실제로 전달됐는지 검사하고 모르는 옵션을 무시하지 않는다. 이 고침은 B 묶음 첫 작업이다.
14. **측정 목표(B):** p01·p07·p09의 불변식 9절(각 3절)을 모두 지우고 증명 성공이 최소 목표다. 이것은 정제나 구간 분석의 효과 지표가 아니다. 추론 없음 / 템플릿만 / (C 뒤) 템플릿+구간을 같은 입력에서 비교한다. p03(루프 안 반환)·p05·p08(변경 배열)·p10(나머지 연산·중첩 루프)는 진단 표본, p02·p06은 `max/min` 집계 시험을 대신하지 않으므로 별도 `max/min` 통과·거부 표본을 둔다. 후보·회차·solver 호출 수, 생성·기호 실행·최종 검증 시간, trace 크기, 예산 폐기 수를 보고한다. 정제(A)의 작성량 감소·실행 경계 검사 비용은 따로 잰다.
15. **필수 거부 표본(B):** 거짓 후보의 첫 진입, 한 번만 유지되는 후보, 의존 후보 제거 뒤 실패, 바깥 후보 제거로 안쪽 증명이 깨지는 중첩 루프, 잘못된 저장 직후 반환, 전체 배열 교체 뒤 옛 길이·원소 요약 사용, 잘못된 루프 조건 인덱싱, 보호 없는 빈 `max/min`, 잘못된 사용자 불변식 — 각각 하나씩.
16. **C 결정(2026-11-11, B 측정 뒤, RESULTS 29절):** 구간 분석(C)은 지금 착수하지 않는다. 불변식을 지운 pruv_agg에서 템플릿만으로 4/10(p01·p02·p07·p09) 증명, 남은 6개 중 비관계형 구간으로 풀릴 것은 p10 하나로 보이고 나머지(p03·p04·p05·p06·p08)는 관계형·양화 불변식이 필요하다. 다음 후보는 값 범위 템플릿(초기값·갱신 기반 `x >= 0`류)과 관계 템플릿(정렬·출력 배열 접두)이며, 착수 시 이 문서에 새 결정으로 적는다. `--infer` 기본 켜기도 아직 하지 않는다(측정 입력이 작음, 후보 질의 하나의 시간 초과가 함수 전체를 실패시키는 설계의 실사용 영향 미측정).

## 1. 정제 타입 문법과 의미

### 1.1 지원 범위

**결정:** 첫 판은 `i64`의 값 범위, `[i64]`의 원소 범위와 길이 상한을 지원한다. 사용 위치는 함수 매개변수·반환 타입·`let`·`let mut`이다.

| 위치 | 첫 판 |
|---|---|
| 함수 매개변수 | 스칼라·배열 정제 허용 |
| 함수 반환 타입 | 스칼라·배열 정제 허용 |
| `let`, `let mut` | 스칼라·배열 정제 허용 |
| 구조체 필드·열거형 payload | 정제 주석 금지 |
| `Option<i64>`, `Result<i64>` 내부 | 정제 주석 금지 |
| 사용자 타입 전체의 조건 | 기존 `requires`·`ensures` 사용 |

필드 정제는 뒤로 미룬다. 현재 구조체·열거형은 생성, 중첩 필드 대입, 패턴 바인딩, 외부 경계, 루프의 루트 전체 havoc에 일관된 처리가 필요하다. 이를 첫 판에 포함하면 배열 입력과 누적 루프의 작성량을 줄이는 목표보다 구현 범위가 커진다. 배열 필드는 현재도 금지다(`SPEC.md:132`, `pruvc/check.py:84`).

### 1.2 문법과 경계

```pruv
fn sum_array(
  a: [i64 | -1_000_000_000..1_000_000_000; ..1_000_000]
) -> i64 {
  // ...
}

fn clamp_input(x: i64 | 0..100) -> i64 | 0..100 {
  return x;
}

let mut count: i64 | 0..100 = 0;
let values: [i64; ..100] = alloc(100, 0);
let bounded: [i64 | -10..10] = copy(values);
```

```text
scalar-refinement := i64 "|" signed-int ".." signed-int
array-refinement  := "[" i64 ["|" signed-int ".." signed-int]
                            [";" ".." unsigned-int] "]"
```

- 정제 주석의 `L..U`는 **양 끝을 포함하는 값 범위**다.
- 길이 주석 `..N`은 `0 <= len(a) && len(a) <= N`이다.
- 원소 범위와 길이 상한은 각각 생략할 수 있다.
- 스칼라·원소 경계는 `i64` 범위의 정수이며 `L <= U`여야 한다.
- 길이 상한은 `0 <= N <= 2^40`이다. `N = 0`은 빈 배열만 허용한다.
- 경계에는 정수 리터럴만 허용한다. 변수 참조, `len`, 산술식, 다른 인자에 의존하는 범위는 기존 계약으로 쓴다.
- `bool`, `()`, 사용자 타입에 `|`를 붙일 수 없다.
- 기존 `[i64]`·`i64` 문법은 그대로다.

**근거:** 청사진 예제의 "원소 범위·길이 상한"을 기존 예제의 `<=` 계약과 직접 대응시킨다. 다만 기존 `forall k in lo..hi`와 집계의 반복 범위는 계속 **상한 제외**다(`SPEC.md:89`, `SPEC.md:107`). 값 범위 주석과 반복 범위의 차이는 명세와 경계 시험에 명시한다. 모든 `..`를 반열린 범위로 통일하는 대안은 표기는 단순하지만 청사진의 상한을 그대로 옮길 수 없어 채택하지 않는다.

**리터럴 결정:** `1e9`, `1e6`은 이번 단계에서도 허용하지 않는다. 청사진 예제는 다음처럼 명세화한다.

```pruv
a: [i64 | -1_000_000_000..1_000_000_000; ..1_000_000]
```

현재 명세와 lexer는 십진 숫자와 `_` 구분자만 지원한다(`SPEC.md:14`, `pruvc/vparser.py:13`). 지수 표기를 위해 일반 리터럴 문법까지 확장하지 않는다. 정제 경계의 지수 표기는 `parse/refinement_syntax`로 거부하고 십진 표기를 제안한다.

### 1.3 타입 체계와 펼치기

**결정:** 기본 타입의 동일성·ABI·값 표현은 바꾸지 않는다. 정제는 선언에 붙는 검증용 주석이며, 논리적 의미는 기존 계약으로 펼친다.

현재 Python의 `Type`은 이름 하나이고 Rust의 `Type`은 문자열이다. 검사기는 기본 타입의 정확한 일치를 검사한다(`pruvc/vast.py:9`, `pruvc/check.py:322`, `pruvc-rs/crates/pruv-core/src/ast.rs:5`). 새 종속 타입 체계보다 이 구조를 유지하는 편이 두 구현과 두 출력 뒷단의 일치를 지키기 쉽다.

`R(T, v)`를 정제 타입 `T`가 값 `v`에 요구하는 조건으로 정의한다.

```text
R(i64 | L..U, x)
  = L <= x && x <= U

R([i64 | L..U; ..N], a)
  = 0 <= len(a) && len(a) <= N
    && (forall k in 0..len(a): L <= a[k] && a[k] <= U)
```

원소 범위가 없으면 `forall`을 만들지 않는다. 길이 상한이 없으면 기존 배열 길이 조건 `0..2^40`을 따른다.

| 위치 | 펼쳐지는 의미 |
|---|---|
| 매개변수 `p: T` | 함수의 합성 `requires R(T, p)` |
| 반환 타입 `T` | 합성 `ensures R(T, result)` |
| 지역변수 선언 | 초기값 평가·바인딩 뒤 `assert R(T, x)`에 해당하는 의무 |
| 정제 지역변수 재대입 | 새 값 저장 뒤 같은 정제 조건의 의무 |
| 정제 배열 원소 대입 | 기존 인덱스·산술 의무에 저장 값의 원소 범위 의무 추가 |
| 정제 지역변수를 변경하는 루프 | 해당 정제 조건을 필수 불변식으로 추가 |

합성 매개변수 계약은 매개변수 선언 순서로, 사용자 `requires`보다 앞에 둔다. 배열은 길이 조건 뒤 원소 조건 순서다. 반환 정제는 사용자 `ensures` 앞에 둔다. 사용자 계약끼리의 순서는 바꾸지 않는다.

지역 정제는 초기화 시 한 번만 검사하는 주석이 아니다. `let mut`의 재대입과 원소 저장에서도 유지해야 한다. 따라서 다음은 증명 모드에서 거부한다.

```pruv
let mut x: i64 | 0..100 = 0;
x = 101;
```

지역 정제에서 나온 필수 불변식은 자동 추론 후보와 구분한다. Houdini가 삭제할 수 없으며, `--no-infer`에서도 남는다. 루프 진입과 보존을 증명하지 않고 `havoc()`에 정제 사실을 무조건 넣어서는 안 된다.

펼치기는 평가 횟수를 늘리지 않는다. 초기화·대입·반환 식을 한 번 평가한 값을 대상으로 의무를 만든다. 특히 `a[i] = f()`는 현재의 인덱스→값 평가 순서를 유지한다(`SPEC.md:83`, `pruvc/verify.py:718`).

### 1.4 하위 타입과 대입 규칙

정제 포함 관계는 같은 기본 타입 사이에서만 성립한다.

```text
i64 | L1..U1 <: i64 | L2..U2
  iff L2 <= L1 && U1 <= U2
```

배열은 원소 범위 포함과 길이 상한 포함을 모두 요구한다. 정제가 없는 기본 타입은 해당 정제 조건이 없는 경우다.

실제 대입·인자 전달 규칙은 다음 하나로 통일한다.

> 기본 타입이 같고, 현재 경로의 사실로 대상 정제 조건을 증명할 수 있어야 한다.

따라서 정제 없는 `i64`도 `if`나 `requires`로 범위가 확인되면 정제된 위치에 들어갈 수 있다. 선언 범위의 포함 관계는 빠른 판정에 사용할 수 있지만, 포함 관계가 불분명하다는 이유만으로 타입 단계에서 거부하지 않는다.

- 산술 결과 타입은 기본 `i64`다. 산술에서 정제 타입을 임의 합성하지 않는다.
- 기본 타입 불일치는 기존 `type_mismatch`다.
- 배열 별칭·소유 규칙은 유지한다. 정제 포함 관계로 `array_alias`를 우회할 수 없다.
- 배열 매개변수는 계속 읽기 전용이다. 가변 별칭의 공변성은 도입하지 않는다.
- 정제 배열의 전체 재대입은 원소·길이 조건을 모두 증명한다.
- 원소 저장은 길이를 바꾸지 않으므로, 기존 배열 정제와 새 원소 범위로 전체 정제 보존을 증명한다.

현재 배열 생성·복사·반환 제한은 `pruvc/check.py:307`에 있다.

### 1.5 오류 코드

| stage | code | 조건 |
|---|---|---|
| parse | `refinement_syntax` | 빠진 경계, 경계의 비리터럴·지수 표기 등 잘못된 정제 문법 |
| type | `refinement_position` | 필드·payload·Option/Result 내부 등 미지원 위치 |
| type | `refinement_base` | 지원하지 않는 기본 타입의 정제 |
| type | `refinement_bounds` | 역전된 범위, i64 밖 경계, 잘못된 길이 상한 |
| verify | `refinement_init` | 지역 초기값 정제를 증명하지 못함 |
| verify | `refinement_assign` | 재대입·원소 저장의 정제를 증명하지 못함 |

합성 매개변수·반환 계약은 기존 `call_requires`·`ensures`를 사용한다. 필수 불변식 실패는 기존 `invariant_entry`·`invariant_preserved`, 정의역 실패는 `contract_domain`·`variant_domain`이다. solver가 결론을 못 내리는 경우는 기존 `verify_unknown`을 유지한다.

모든 합성 의무는 원래 주석의 위치와 종류를 보존한다. 메시지에는 "반환 정제", "매개변수 a의 원소 범위"처럼 출처를 표시하며 사용자가 작성하지 않은 내부 변수 이름을 수정 대상으로 제시하지 않는다.

### 1.6 실행 검사와 안전 모드

**결정:** 정제를 기존 계약으로 펼친다는 원칙에 맞춰 `docs/M0_CONTRACTS.md`의 실행 정책을 그대로 따른다.

- 합성 매개변수 `requires`는 공개 함수 진입에서 실행 검사한다.
- 한 진입의 합성·사용자 `requires`가 **동일한 2^30 반복 예산**을 공유한다. 정제별 예산을 새로 만들지 않는다.
- 원소 `forall`은 실제 검사한 원소마다 1을 소비한다. 빈 배열과 단락으로 건너뛴 식은 소비하지 않는다.
- 길이 상한을 먼저 검사하므로 길이가 상한을 넘으면 원소 순회 전에 실패한다.
- 예산 초과는 기존 `pruv: requires undefined: contract iteration budget exceeded`, 종료 코드 101이다.
- 정제는 기존 계약의 정적 반복 횟수 제한을 새로 만들지 않는다. 여러 배열 계약의 합산 비용은 실행 예산으로 제한한다.
- 반환 정제·지역 정제 의무·필수 및 추론 불변식은 실행 코드에서 지운다.
- `--no-verify`는 정제의 논리적 성립을 증명하지 않는다. 기존처럼 인덱싱·산술·할당의 실행 안전 검사와 공개 경계 `requires` 검사는 남긴다.
- 안전 모드의 내부 호출은 검사 진입점을 통한다. 증명 모드의 내부 호출은 증명된 `requires`를 바탕으로 본체로 간다.
- `--trust-callers`는 합성 정제를 포함한 공개 경계 검사도 생략한다. 정적 증명 의무를 없애지는 않는다.

따라서 `--no-verify`에서 지역 정제나 반환 정제까지 실행 보장한다고 설명해서는 안 된다. 이는 현재 `assert`·`ensures`·`invariant`가 안전 모드에서도 지워지는 정책과 같다(`docs/M0_CONTRACTS.md:28`, `pruvc/codegen.py:494`).

## 2. Houdini식 불변식 자동 추론

### 2.1 후보 생성

**결정:** 검사된 AST와 정제 펼치기 결과에서 유한한 후보를 만든다. 변수 이름이 `i`, `s`, `count`인지에 의존하지 않고 초기화·조건·갱신·계약의 구조를 이용한다.

| 출처 | 후보 예 | 제한 |
|---|---|---|
| 구간 분석 | `0 <= i`, `i <= 100`, `x == 0` | 유한 경계만 전달 |
| 루프 조건·초기화 | `0 <= i && i <= len(a)` | 초기값·증가량·조건을 함께 확인 |
| 정제·명시적 원소 전제 | `forall k in 0..len(a): L <= a[k] && a[k] <= U` | 변경되는 배열이면 보존 증명 필요 |
| 합 누적 | `s == sum(k in 0..i: a[k])` | 초기값·한 칸 갱신·불변 입력 확인 |
| 개수 누적 | `c == count(k in 0..i: a[k] < x)` | 조건부 `+1` 패턴 |
| 최대·최소 누적 | `0 < i ==> m == max(k in 0..i: a[k])` | 빈 접두 구간 보호 필수 |
| 누적값 범위 | `L*i <= s && s <= U*i` | 항의 범위와 처리 개수에서 생성 |
| 개수 범위 | `0 <= c && c <= i` | 개수 누적 패턴 |

구간 분석만으로 `s <= U*i` 같은 관계를 얻었다고 주장하지 않는다. 이는 별도의 누적 템플릿이다.

후보 생성기는 다음을 지원한다.

1. `i = 0`, `i = 1` 등 시작값과 `i = i + 1`인 전진 루프.
2. `n = len(a)` 같은 변경되지 않는 길이 별칭.
3. `s = s + e(i)`와 조건부 개수 증가.
4. `if e(i) > m { m = e(i); }` 및 최소값의 대칭 형태.
5. 명시적 집계 후조건의 상한을 진행 변수로 바꾼 접두 후보.
6. `return Ok(s)`처럼 결과 payload와 누적변수의 연결이 구문상 확인되는 경우.
7. 원소 범위의 곱에서 얻는 내적 항 범위.

초기 누적값이 0이 아니면 그 값을 포함하는 후보를 만들거나 패턴을 포기한다. 시작 인덱스가 1인 최대값 루프에 합의 빈 접두 초기화를 적용하지 않는다.

기존 집계의 한 칸 펼치기 보조정리를 그대로 사용한다. 후보마다 새로운 전역 귀납 공리를 추가하지 않는다. `verify.py:545`의 집계 모델은 임의 구간 분할이나 최대값의 분배 성질을 제공하지 않는다. `RESULTS.md:49`도 최대 부분합을 단순 `max` 계약으로 증명하지 못하는 한계를 기록한다.

### 2.2 제거 알고리즘과 건전성

각 루프 `ℓ`에 대해 다음을 둔다.

- `Uℓ`: 사용자 불변식과 지역 정제의 필수 불변식. 삭제 불가.
- `Cℓ`: 자동 후보. 삭제 가능.
- `Iℓ = Uℓ ∧ ∧Cℓ`.

한 함수의 중첩 루프까지 함께 다루는 고정점 계산을 한다.

```text
모든 루프 후보를 생성하고 정규화한다.
반복:
    이번 회차의 후보 집합을 고정한다.
    함수와 루프를 정해진 순서로 기호 실행한다.
    각 후보의 진입·보존 및 정의역 의무를 검사한다.
    실패하거나 결론을 못 얻은 후보 ID를 수집한다.
    회차 끝에 실패 후보를 일괄 제거한다.
    제거가 없으면 종료한다.
확정 후보를 붙인 프로그램을 새 검증 상태에서 전체 재검증한다.
```

검사해야 할 의무는 다음과 같다.

- **진입:** 루프에 도달하는 모든 경로에서 후보가 정의되고 참이다. 루프 자신의 후보를 진입 가정으로 사용하지 않는다.
- **보존:** 변경 변수를 havoc한 뒤 현재 `Iℓ`과 루프 조건을 가정하고 본문을 한 번 실행한다. 다음 반복으로 돌아오는 모든 경로에서 후보가 정의되고 참이어야 한다.
- **종료 경로:** 본문에서 `return`한 경로에는 back-edge 보존을 요구하지 않는다. 반환 계약은 최종 검증에서 검사한다.
- **정의역:** 후보의 값으로 자기 정의역을 정당화하지 않는다. `max/min`은 후보 내부의 단락 가드로 빈 범위를 보호한다.

한 후보가 다른 후보를 필요로 할 수 있으므로, 후보가 제거되면 나머지 후보도 다시 검사한다. 한 번 성공한 후보를 영구 확정하지 않는다. 중첩 루프도 같은 회차의 후보 집합을 사용해 검사하여, 바깥 후보가 빠졌는데 안쪽 증명 결과만 남는 일을 막는다.

탐색 중 `Uℓ`을 귀납 가정으로 사용할 수 있지만, 사용자 불변식의 진입·보존 실패를 숨기거나 삭제하지 않는다. 최종 전체 검증에서는 다음이 모두 성공해야 한다.

- 사용자·필수·추론 불변식의 진입·보존·정의역
- 모든 인덱스·산술·할당 의무
- 호출 전제와 반환 후조건
- `assert`
- `decreases`의 정의역·비음수·엄격 감소

**추론은 `decreases`를 만들거나 생략하지 않는다.** 현재 parser가 요구하는 정확히 하나의 `decreases`를 유지한다(`pruvc/vparser.py:247`).

탐색용 오류·`seen`·fresh 번호·집계 캐시·보조정리를 최종 검증 상태에 재사용하지 않는다. 현재 `prove()`는 오류 기록과 중복 억제를 함께 하므로, 이를 후보 판정용 불리언 함수처럼 직접 사용해서는 안 된다(`pruvc/verify.py:254`).

### 2.3 예산과 결정성

**결정:** 후보 선택은 경과 시간 대신 정해진 순서와 논리적 자원 예산으로 제어한다.

초기 기본값은 다음과 같다. 수치는 성능 측정 전의 제안값이다.

| 항목 | 초기값 |
|---|---|
| 루프별 후보 상한 | 64개 |
| 함수별 탐색 solver 호출 상한 | 512회, 보조정리 재시도 포함 |
| 탐색 질의별 z3 `rlimit` | 100,000 |
| 탐색 질의별 시간 안전장치 | 500ms |
| 함수별 추론 시간 안전장치 | 5초 |

- 64개 제한은 정렬 후 적용하고, 버린 수를 진단에 기록한다.
- 질의 횟수 제한 전에 고정점이 완성되지 않으면 **그 함수의 자동 후보를 모두 버리고** 기존 검증으로 진행한다. 일부 검사한 집합을 완성된 불변식으로 취급하지 않는다.
- 일반 `sat`·결정론적 자원 한계의 `unknown`은 해당 후보를 제거한다.
- 벽시계 시간 안전장치가 발동하면 `verify/inference_timeout`으로 컴파일을 중단한다. 시간에 따라 서로 다른 후보 집합을 골라 성공시키지 않는다. 수정 안내는 `--no-infer` 또는 명시적 불변식이다.
- 최종 검증의 기존 8,000ms 질의 제한은 별개다(`pruvc/verify.py:8`).
- 후보 cap, 회차, 질의 수, 자원 설정은 버전 있는 추론 설정으로 두 구현이 공유한다.

시간 안전장치에 걸린 실행까지 같은 결과를 보장할 수는 없다. 이는 정상 완료 실행의 결정성 계약과 구분하며, 대조 시험에서 성공으로 숨기지 않는다.

후보 ID와 순서는 다음으로 고정한다.

```text
함수 선언 순서
→ 루프 AST 전위 순번
→ 후보 종류의 고정 번호
→ 알파 정규화된 식의 구조 키
```

묶인 변수는 내부 예약 이름으로 정규화하고, 정수는 십진 정규형을 쓴다. 해시맵 순서, 객체 주소, 반례 모델의 열거 순서는 후보 선택에 쓰지 않는다. 양화·논리식 자식 순서를 무분별하게 교환하는 정규화도 하지 않는다. 단락 정의역이 달라질 수 있기 때문이다.

사용자 불변식의 상대 순서는 유지하고, 필수 정제 불변식과 자동 후보의 배치 규칙을 고정한다. 자동 후보는 자체 가드나 앞선 고정 순서의 조건으로 정의역을 증명할 수 있어야 한다. 뒤의 추론 후보를 이용해 앞의 사용자 계약 정의역을 소급 정당화하지 않는다.

### 2.4 Python·Rust SMT-LIB 대조

현재 대조는 최종 성공 여부만 보지 않는다. Python 어댑터는 각 solver 호출 직전 SMT 텍스트를 기록하며, `tests/diff_trace.py`는 그 문자열을 비교한다(`tests/diff_py_adapter.py:199`, `tests/diff_trace.py:302`).

따라서 새 추론 trace에는 다음을 추가한다.

- 단계: `inference` 또는 `verification`
- 함수·루프·회차·후보 ID
- 의무 종류: 진입, 보존, 정의역
- 실제 solver 옵션: timeout, rlimit, 고정 seed
- 보조정리 사용 여부, SMT-LIB 원문, 판정
- 후보 제거·예산 종료 사유

현재 Python 어댑터는 timeout을 상수로 기록하므로 수정이 필수다. 추론 질의를 누락하거나 500ms 질의를 8,000ms로 표시해서는 안 된다.

두 구현은 fresh 이름, 경로 순회, havoc 순서, 집계 등록 순서, assertion 삽입 순서, 보조정리 없는 시도→있는 시도까지 맞춘다. 반례 값 차이는 기존 허용 범위를 유지하되, 반례 내용으로 후보를 선택하지 않는다.

기존 입력에 `--no-infer`를 사용하면 기존 최종 검증 SMT와 오류가 유지되는 것을 별도 관문으로 삼는다.

### 2.5 사용자 진단과 끄기

- 기본 증명 모드에서 추론을 켠다.
- `--no-infer`: 자동 후보 생성·Houdini를 끈다. 정제의 필수 의무는 유지한다.
- `--show-inferred`: stderr에 정해진 키 순서의 JSON Lines로 추론 결과를 표시한다.
- `--no-verify`: 추론도 실행하지 않는다. 표시 옵션을 함께 쓰면 `skipped_no_verify` 상태를 낸다.

표시에는 함수·루프 위치, 붙여 넣을 수 있는 `invariant ...` 문장, 출처, 생성·채택·탈락 수, 예산 상태를 담는다. 최종 검증까지 성공한 결과만 `verified`로 표시한다. 전체 검증 실패 시 탐색에서 살아남은 후보는 `selected`로 구분한다.

기존 stdout의 오류 JSON과 `{"ok": true}` 형식은 유지한다. 생성 소스에 자동 주석을 삽입하거나 사용자 파일을 고치지는 않는다.

## 3. 구간 분석

### 3.1 추상 영역과 대상

**결정:** 첫 판은 비관계형 정수 구간 분석이다.

```text
Interval = ⊥ | [lower, upper]
lower/upper = 정수 또는 -∞/+∞
```

추적 대상은 `i64` 지역변수·매개변수, 배열 길이, 별도로 요약한 배열 원소 범위다. 산술은 임의 정밀도 정수로 계산한다. 분석기의 오버플로가 잘못된 좁은 구간을 만들면 안 된다.

- 기본 `i64` 입력은 i64 전체 범위에서 시작한다.
- 정제와 단순 명시적 `requires`의 경계를 입력 사실로 읽는다.
- `&&`로 결합한 단순 비교는 순서대로 좁힌다.
- 일반 양화식이나 복잡한 논리식을 임의로 수치 경계로 바꾸지 않는다.
- 명시적 `forall k in 0..len(a): L <= a[k] && a[k] <= U`는 정제 원소 범위와 같은 요약으로 인식한다.

새 문법으로 바꾸지 않은 `bench/solutions/pruv_agg`도 측정할 수 있도록 기존 전제의 이 형식을 지원한다.

### 3.2 전달 함수

| 구문 | 처리 |
|---|---|
| 리터럴·변수·단항 부호 | 정확한 구간 전달 |
| `+`, `-`, `*` | 구간 연산, 곱은 끝점 조합 사용 |
| `/`, `%` | 현재 코드의 정의역을 확인할 수 있을 때만 좁힘 |
| 대입 | 이전 대상 구간을 새 구간으로 교체 |
| `if` | 참·거짓 분기 각각 좁힌 뒤 구간의 최소 포함 구간으로 합침 |
| 단락 논리 | 실제 도달 조건 반영 |
| `alloc`, `copy` | 길이·원소 범위 전달 |
| 배열 저장 | 기존 원소 범위와 저장 값 범위를 합침 |
| 함수 호출 | 반환 정제와 지원하는 단순 후조건 사용, 나머지는 기본 범위 |
| `match` | 각 arm 분석 후 합침, arm 지역변수 제거 |
| 미지원 식 | 보수적으로 전체 범위 |

산술 안전성을 증명하지 못했는데 결과를 i64 범위로 잘라 "넘치지 않음"을 순환 증명하지 않는다. 계산 결과가 i64 밖으로 나갈 수 있으면 그 가능성을 남기고 기존 검증기에 맡긴다.

변경되지 않는 `n = len(a)`는 별칭 정보로 유지한다. `x <= y` 같은 관계는 독립 구간만으로 정확히 표현할 수 없으므로, 지원되는 루프 경계 관계는 별도 후보 템플릿에 넘긴다.

### 3.3 while 고정점과 위드닝

루프 머리 상태는 초기 진입 상태와 back-edge 상태를 합쳐 계산한다. 본문 분석에는 참인 루프 조건을 적용한다.

- 처음 두 번은 일반 join을 한다.
- 이후 증가하는 끝점은 정해진 임계값으로 위드닝한다.
- 임계값은 0, 1, i64 양 끝, 소스의 관련 상수, 정제 경계와 길이 상한을 정렬·중복 제거하여 만든다.
- 임계값을 넘어 계속 확장하면 무한대로 넓힌다.
- 구현상 반복 제한에 도달하면 바뀌는 성분을 전체 범위로 넓힌다.
- 안정화 후 한 번의 보수적 narrowing을 허용하며, 결과가 추상 전달의 후고정점인지 다시 확인한다.
- 중첩 루프는 동일한 규칙과 고정 순서로 처리한다.

특히 **조건을 적용하기 전 루프 머리 구간**과 본문 안 구간을 구분한다. `while i < n`의 본문 사실 `i < n`을 그대로 불변식으로 제출하면 마지막 반복 후 실패한다. `i <= n`은 별도 경계 후보로 생성해 귀납성을 검사한다.

### 3.4 후보로 전달하는 결과

분석 결과는 다음 정보와 함께 후보 생성기에 전달한다.

```text
루프 ID, 변수/배열 ID, 유한 하한·상한,
길이 별칭, 원소 범위, 출처, 루프 머리/본문/출구 구분
```

유한 하한은 `L <= x`, 유한 상한은 `x <= U`, 같은 양 끝은 `x == C` 후보가 된다. 무한대·전체 범위·도달 불가 상태는 불필요한 후보를 만들지 않는다.

구간 결과는 직접 SMT 가정이나 LLVM 최적화 속성이 되지 않는다. 잘못된 분석 결과라도 Houdini와 최종 검증을 모두 통과해야 사용된다.

## 4. 이번 범위 밖

`BLUEPRINT.md`의 **AI에게 반례를 전달하여 불변식을 제안받는 기능은 이번 단계에서 구현하지 않는다.** 모델 호출, 프롬프트, 외부 서비스, 반례 전송, AI 제안의 캐시·재시도 정책도 범위 밖이다. 이번 추론은 저장소 코드와 계약에서 결정적으로 생성한 유한 후보만 사용한다.

정제 필드, 일반 종속 타입, 임의 술어 정제, 정제 타입 별칭, 종료 척도 추론, 집계의 임의 분할·추가 귀납 보조정리 역시 이번 첫 판에 포함하지 않는다.

## 5. 구현 묶음과 끝 기준

### 5.1 데이터 경계

현재 Python 파이프라인은 `parse → check → verify → gen`이다(`pruvc/pruvc.py:53`). 실제 parser 파일은 `pruvc/vparser.py`다.

다음 경계를 추가한다.

```text
원본 AST
→ 기본 타입 검사 + 정제 검증·펼치기
→ 계약이 펼쳐진 검사 완료 AST
→ 구간 분석·후보 생성·Houdini
→ 확정 불변식 맵을 이용한 전체 검증
→ 기존 Rust/LLVM 코드 생성
```

- `Type`과 `Expr.ty`는 기본 타입만 표현한다.
- `Param`, `Function`의 반환 주석, `Let`에 정제 메타데이터를 명시적으로 둔다.
- `Refinement`는 경계와 원본 위치를 보관한다.
- 합성 의무에는 출처와 고유 ID를 둔다. 같은 주석 위치에서 나온 여러 의무가 기존 `seen` 키에 충돌하지 않게 한다.
- 추론 결과는 `LoopId → 후보 목록`의 별도 불변 자료로 전달한다. 검사 완료 AST를 탐색 회차마다 수정하지 않는다.
- 기본 타입용 `wf()`에 정제 조건을 섞지 않는다. 정제는 증명해야 하는 계약이다.

아래 묶음은 순차 통합 단위다. 같은 파일을 여러 묶음에서 고치는 경우 앞 묶음 완료 뒤 진행한다.

### 5.4 회귀와 새 시험 관문

완료 시에는 Python·Rust 각각에 대해 다음을 요구한다.

1. 기존 363개 회귀 행을 삭제하지 않고 두 뒷단에서 유지한다.
2. 기본 추론 모드와 `--no-infer`에서 기존 기대 결과를 확인한다.
3. 추론 때문에 기존 거부 판정이 달라지면 실제 버그인지, 증명 불완전성 시험인지 개별 조사한다. 기대값을 일괄 갱신하지 않는다.
4. 새 시험은 별도 수로 보고하고 전체 수를 함께 기록한다.
5. 기존 CLI 186개도 유지하고 새 옵션 시험을 추가한다.

새 시험에는 다음이 반드시 포함된다.

- 스칼라 양 끝, 범위 밖 한 칸, i64 최솟값·최댓값.
- 배열 길이 0·N·N+1, 원소 양 끝, 역전 범위·잘못된 상한·미지원 위치.
- 정제 없는 값이 경로 조건으로 좁혀져 통과하는 사례와 증명되지 않아 거부되는 사례.
- `let mut` 재대입·전체 배열 교체·원소 저장·루프 보존 위반.
- 합성 정제가 사용자 계약보다 먼저 평가되는 경계 검사.
- 여러 합성·명시적 `requires`의 예산 공유. 기존 시험용 작은 `--contract-budget`으로 경계 확인.
- 초기 진입 실패 후보, 한 번만 유지되는 후보, 의존 후보 제거 후 실패하는 후보.
- 잘못된 `max/min` 빈 접두, 배열을 변경해 깨지는 원소 범위.
- 중첩 루프, 조기 반환, 0회 반복, 조건식의 안전성 의무.
- 잘못된 사용자 불변식이 추론 때문에 사라지지 않는 사례.
- 후보·질의 한도, rlimit, 시간 안전장치, `--no-infer`, `--no-verify`.
- Python hash seed를 바꾼 반복 대조와 두 구현의 후보·SMT 순서 대조.

### 5.5 작성량 감소 측정

기준 입력은 `bench/solutions/pruv_agg/p01.pruv`부터 `p10.pruv`까지다. 원본은 보존하고 측정용 사본을 만든다.

- **전체 제거:** 모든 사용자 `invariant`를 지우되 계약·본문·`decreases`는 유지한다.
- **부분 제거:** 하나씩 또는 정해진 그룹으로 지워 어느 불변식을 대체하는지 잰다.

| 지표 | 정의 |
|---|---|
| 전체 제거 후 증명 성공 | 10개 함수 중 모든 의무를 증명한 수 |
| 대체 불변식 수 | 삭제한 명시 불변식 절 수와 남긴 절 수 |
| 추론 효과 | 같은 변형 입력의 추론 켬·끔 성공 차이 |
| 비용 | 함수별 후보·회차·질의 수, 시간 중앙값·상위 지연 |
| 안정성 | 동일 입력 반복·hash seed·Python/Rust 판정 및 SMT 일치 |
| 건전성 회귀 | 잘못된 변이의 새 통과 수 |

**첫 판 완료 목표는 전체 제거한 p01(합), p07(개수), p09(내적) 세 함수의 증명 성공**으로 정한다. 필요한 접두 집계와 누적 경계가 코드에 명확히 대응하기 때문이다. 네 집계 모두를 검증하기 위해 `max/min` 전용 통과·거부 표본도 별도로 둔다.

p02의 `forall/exists` 최대값 특성화, p04의 이분 탐색 구간, p05·p08의 출력 배열 접두, p06의 최대 부분합은 측정 결과를 공개하되 이 첫 판의 필수 성공 수에는 넣지 않는다. 위 성공 수는 **목표이며 현재 측정값이 아니다.**

## 6. 위험과 열린 문제

| 위험 | 이번 결정과 검토 지점 |
|---|---|
| 정제의 무조건 가정 | `wf()`와 분리하고 초기화·저장·루프 보존 의무를 확인한다. |
| 후보 사이의 순환 정당화 | 진입 검사, 제거 후 재검사, 새 상태의 전체 검증을 필수로 한다. |
| 정의역 자기 정당화 | 후보 값보다 정의역을 먼저 검사한다. 단락·빈 집계를 시험한다. |
| 변경 배열의 옛 범위 재사용 | 저장·전체 재대입·havoc 뒤 보존을 다시 증명한다. |
| 추론 상태 누출 | 탐색의 `seen`, fresh 번호, 집계 캐시를 최종 검증과 격리한다. |
| 양화식으로 인한 비용 급증 | 후보 cap과 두 단계 집계 증명을 유지한다. 기존 정의역 가정이 p06을 크게 느리게 한 기록을 고려한다(`docs/M0_CONTRACTS.md:21`). |
| SMT 텍스트의 미세한 차이 | 이름·정렬·등록·옵션·직렬화를 전부 대조 대상으로 한다. |
| 시간 제한의 비결정성 | 시간에 따른 부분 후보 채택을 금지한다. 시간 초과 실행은 별도 실패로 보고한다. |
| 안전 모드에 대한 오해 | 실행 안전과 전체 계약 보장을 구분한다. 지역·반환 정제는 안전 모드에서 증명되지 않는다. |
| 닫힌 정제 범위와 반열린 반복 범위 | 문서·오류 안내·경계 시험으로 구분한다. 공개 문법 확정 전 재검토할 지점이다. |
| 벤치마크 과적합 | 변수 이름 변경, 조건 방향·초기값·반환 포장 변형, 음수 원소와 빈 입력을 새 시험에 넣는다. |

열린 문제:

- 제안한 64개 후보·512회 질의·rlimit·시간 안전장치가 실제 프로그램에 적합한지 측정해야 한다.
- 외부·내부 루프 전체를 재검사하는 비용이 크면 이후 증명 의존성 캐시를 검토한다. 첫 판은 단순하고 검토 가능한 전체 재검사를 택한다.
- 비관계형 구간 분석의 한계가 실제 실패의 주원인인지 측정한 뒤 관계형 분석을 검토한다.
- 필드 정제는 생성·대입·match·외부 경계의 의미를 별도 설계한 뒤 도입한다.
- `max/min` 동등식과 기존 `forall/exists` 특성화를 연결하는 보조정리는 별도 건전성 검토가 필요하다.
