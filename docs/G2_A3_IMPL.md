# G2 A3 Implementation Spec: `[u8]` Rust Source Backend

Status: implementation contract for batch A3 (written by the main agent). Both implementations (Python `pruvc/`, Rust `pruvc-rs`) emit the text below **byte for byte**. `tests/diff_rust.py` compares the Rust sources generated by the two implementations byte by byte.

## 0. Scope and decisions

1. A3 opens `[u8]` in the **Rust source backend** (`--backend rust`). The LLVM backend (`--backend llvm`, `--also-llvm`, and every path that uses llvmgen, such as the Rust implementation's `--emit ll|obj|exe`) is rejected with `codegen/unsupported_type` until A4 (decision 16).
2. **`runtime.c` and `pruvc/src/runtime.rs` are not changed in A3; they move to A4.** Reason: `runtime.c` is used only by the LLVM backend, and putting the v2 host helper externs (`pruv_host_alloc_v2` etc.) into the `-DPRUV_RUST_ALLOCATOR` variant would break linking with the existing bindings, which do not yet define those helpers. The v2 runtime and the v2 bindings must come in together in the same batch (A4). All that could go into the runtime in A3 is dead code with no consumer, so we do not add it.
3. The generated Rust source of programs that use only the existing `[i64]` **does not change by even one byte**. The u8 helpers are appended separately, only when the program uses `[u8]`.
4. The new failure wording in safe mode (`--no-verify`) (the prefix in the table in §5.3):
   `pruv: element out of range: <v> (u8 0..=255)` — panic, exit 101 (Rust panic). A4's `runtime.c` also uses this wording.
5. Check order (the same as the proof-obligation order): a store checks **index → value range**, alloc checks **length → value range**. The alloc value range is checked even when the length is 0.

## 1. Shared type queries (typeinfo)

Python `pruvc/typeinfo.py` / Rust `pruv-core/src/typeinfo.rs`.

- Keep the current `first_g2_unimplemented(prog)` walk (per function: parameters → return type → body lets, depth-first in source order) as is, and make it take a **list of internal names to skip**, `skip`.
  - Py: `first_g2_unimplemented(prog, skip=())` — the first place where `is_array(ty) and ty != ARRAY and ty.name not in skip`.
  - Rs: `first_g2_unimplemented(prog: &Program, skip: &[&str])`.
- `g2_unimplemented_error(prog, stage, layer=None, skip=(), fix=None)` (Rs: `g2_unimplemented_error(prog, stage, layer: Option<&str>, skip: &[&str], fix: Option<&str>)`):
  - message: `"%s arrays are not supported yet: the %s layer is not implemented" % (type_name(ty), layer or stage)`
  - fix: `fix or "use [i64] for now"`
  - code `unsupported_type`, stage `stage`, location the same as now.
- New function `uses_array_type(prog, name)` (Rs: `uses_array_type(prog: &Program, name: &str) -> bool`): true if the same walk finds at least one place where `ty.name == name`.
  - A `[u8]` value necessarily comes from the parameter, return, or let type of some function (decision 6: the u8 of alloc appears only in typed-let, reassignment, and return positions), so this walk is enough.
- All existing call sites pass the new arguments as defaults to keep today's behavior (Rs: `None, &[], None`).

## 2. Driver guard

Py `compile_file` in `pruvc/pruvc.py`, Rs `compile` in `pruvc-rs/crates/pruvc/src/driver.rs`. The position stays at the current guard spot (after verify, before generation).

```
Paths that use llvm (Py: backend == "llvm" or also_llvm; Rs: a.kind is not Rs or a.also_llvm is Some):
    g2_unimplemented_error(prog, "codegen", layer="llvm codegen", fix="use --backend rust or [i64] for now")
Otherwise (pure Rust source backend):
    g2_unimplemented_error(prog, "codegen", skip=("array_u8",))
```

Resulting diagnostic (example):
`{"stage": "codegen", ..., "code": "unsupported_type", "message": "[u8] arrays are not supported yet: the llvm codegen layer is not implemented", "fix": "use --backend rust or [i64] for now"}`

The generators' own guards:
- `codegen.py` `gen_rust` / `codegen.rs` `gen_rust`: `g2_unimplemented_error(prog, "codegen", skip=("array_u8",))` — the message format is the same as now (`unsupported_type: ...`).
- Do **not change** the guards in `llvmgen.py` and `llvmgen.rs` (they are lifted in A4).

## 3. Type spelling

`rty` (Py `codegen.py`, Rs `emit_common.rs`):

| Internal name | param=True | param=False |
|---|---|---|
| `array` | `&[i64]` | `::std::vec::Vec<i64>` |
| `array_u8` | `&[u8]` | `::std::vec::Vec<u8>` |

`array_bool` is not handled here (the parser still rejects it; if met, Py raises an exception as now, and Rs keeps its current behavior — however, Rs `rty` is `other => other.to_string()`, so it can be left as is).

## 4. Finding the element type

- **Read `a[i]` (both code and contracts)**: `array_elem(e.array.ty)` (Rs: `array_elem_name(expr_ty(array))`). The checker attaches a ty to every expression, including nodes created by refine.
- **Store `NAME[i] = v`**: IndexAssign has no ty, so the generator keeps a **variable type table**.
  - At function start, put the parameter name → type into it.
  - When emitting a `Let`, put that name → `st.type` into it.
  - For each `block` (statement list), copy the table on entry and restore it on exit (so that the same name in sibling blocks does not get mixed up).
  - If the type of the name being stored into is `array_u8`, it is a u8 store; otherwise it stays as it is now.
- **alloc**: if the Call node's ty is `array_u8`, it is a u8 alloc (the checker attaches it that way only in the three places of decision 6).
- **Rewriting `match_sorted_requires`** (Py `cquant`, the same place in Rs): for the two newly created `Var(name=arr)` (the `Index` array), put **the ty of the original array variable** (the ty of the `len(a)` argument Var in `e.hi`), and for the new `Index` node's ty, put the ty of the original body `a[i]` Index (the ty of an integer-array read is always `i64`, so the Rust implementation leaves it as `Some("i64")`. This ty is not used in the output text). That way the sorted requires of a u8 array picks `pruv_cidx_u8`. The output bytes of `[i64]` do not change.

## 5. Generated text (exact strings)

In the following, `I`, `X`, `N`, `V` are the results of expression generation as now, `NAME` is the variable name, `AREF` is the result of the current `arr_ref`, and `A` is the result of the array expression used by reads today. The text of the `[i64]` path does not change at all.

### 5.1 Proof mode (verified=True)

| Place | `[u8]` output |
|---|---|
| Read `a[i]` | `((unsafe { *A.get_unchecked((I) as usize) }) as i64)` |
| Store `NAME[i] = x` | `{ let pruv_i: i64 = I; let pruv_x: i64 = X; unsafe { *NAME.get_unchecked_mut(pruv_i as usize) = pruv_x as u8; } }` |
| `alloc(n, v)` | `{ let pruv_n: i64 = N; let pruv_v: i64 = V; vec![pruv_v as u8; pruv_n as usize] }` |

(In proof mode, `as u8` does not truncate, because only values for which `elem_range` is proven are accepted.)

### 5.2 Safe mode (verified=False)

| Place | `[u8]` output |
|---|---|
| Read `a[i]` | `pruv_get_u8(AREF, I)` |
| Store `NAME[i] = x` | `{ let pruv_i: i64 = I; let pruv_x: i64 = X; pruv_set_u8(&mut NAME, pruv_i, pruv_x); }` |
| `alloc(n, v)` | `pruv_alloc_u8(N, V)` |

### 5.3 Contracts (requires runtime check, i128)

| Place | `[u8]` output |
|---|---|
| Read `a[i]` | `pruv_cidx_u8(ARR, I)` (`ARR` is the result of the current `carr`) |

`len`, `copy` (`X.to_vec()`), function-call arguments, `return`, and reassignment have the same text. However, the condition for **borrowing an array to pass as a call argument** is widened from `x.ty == ARRAY` to `is_array(x.ty)` (Rs: `expr_ty(x) == Some("array")` → `is_array_name`).

### 5.4 Prelude to append

Appended only when `uses_array_type(prog, "array_u8")` is true.

- Safe mode: put `SAFE_PRELUDE_U8` in the **element right after** the one where `SAFE_PRELUDE` is put in the output list.
- When there is a requires runtime check (`has_req and not trust`): put `CONTRACT_PRELUDE_U8` in the **element right after** the one where `CONTRACT_PRELUDE` is put (before the contract mirror types `ctypes`).

The Python output joins the elements with `"\n"` and appends `"\n"` at the end. Each constant ends every line with `\n`, so one blank line appears between constants. The Rust implementation must emit the same bytes.

`SAFE_PRELUDE_U8` (exact text, the last line also ends with `\n`):

```
#[allow(dead_code)]
#[cold]
#[inline(never)]
fn pruv_elem_oor(v: i64) -> ! { panic!("pruv: element out of range: {} (u8 0..=255)", v) }
#[allow(dead_code)]
#[inline]
fn pruv_get_u8(a: &[u8], i: i64) -> i64 { a[pruv_idx(i, a.len())] as i64 }
#[allow(dead_code)]
#[inline]
fn pruv_set_u8(a: &mut [u8], i: i64, v: i64) { let k = pruv_idx(i, a.len()); if v < 0 || v > 255 { pruv_elem_oor(v) } a[k] = v as u8; }
#[allow(dead_code)]
#[inline]
fn pruv_alloc_u8(n: i64, v: i64) -> ::std::vec::Vec<u8> { if n < 0 || n > (1i64 << 40) { pruv_ovf("alloc length outside 0..2^40") } if v < 0 || v > 255 { pruv_elem_oor(v) } vec![v as u8; n as usize] }
```

`CONTRACT_PRELUDE_U8` (exact text):

```
#[allow(dead_code)]
#[inline]
fn pruv_cidx_u8(a: &[u8], i: i128) -> i128 { if i >= 0 && i < (a.len() as i128) { a[i as usize] as i128 } else { pruv_ud("array index out of range") } }
```
