# G9 problems (recursion, recursive types, buffer fields)

Each solution is one Pruv file `qNN.pruv`. The language rules are in SPEC.md (section 6e, Recursion, recursive types and
buffer fields; the earlier sections for arrays, contracts and `str`). Nothing else is needed.

Rules common to all four problems:

- Define the **public wrappers** with exactly the given names, types and contracts (copy `requires` and `ensures`
  exactly as listed; you may not weaken or drop them, and you may not add `requires`). Recursive and buffer-field types
  cannot appear in wrapper signatures (SPEC 6e, Limits), so wrappers take `i64` and `[i64]` and return `i64` or `bool`.
  Helper functions and types are allowed.
- Use the construct named in each problem ("Required constructs"); `run.py` rejects a file that does not contain them.
- The file must verify (no `--no-verify`) on both compilers and on both backends, and must not panic on the test inputs.
  Allocating functions are written `! alloc`.
- The grader compares the wrapper's result (Rust `Debug` text) with a trusted reference computed in Python.

Type mapping at the wrapper boundary: `i64` is `i64`, `bool` is `bool`, `[i64]` is `&[i64]`.

Build configurations: the Python and the Rust compiler, each with the Rust backend and with the LLVM backend (four
configurations). All four must give the reference results.

Test inputs are generated by `tests()` in `run.py` (seeded). `I = {i64::MIN, -1, 0, 1, 2, 7, i64::MAX}`.

## q01 - recursive array search

Wrappers (no effects):

```pruv
fn find_first(a: [i64], q: i64) -> i64
  requires len(a) <= 1000000
  ensures result == 0 - 1 || (0 <= result && result < len(a))
  ensures result >= 0 ==> a[result] == q && (forall k in 0..result: a[k] != q)
  ensures result < 0 ==> (forall k in 0..len(a): a[k] != q)

fn all_below(a: [i64], t: i64) -> bool
  requires len(a) <= 1000000
  ensures result == (forall k in 0..len(a): a[k] < t)
```

- `find_first`: the smallest index `k` with `a[k] == q`, or `-1` if `q` does not occur.
- `all_below`: true exactly when every element is smaller than `t` (true for the empty array).
- Required constructs: no `while` loop anywhere in the file; the search is done by a recursive function with a
  `decreases` clause.
- Tests: about 20 arrays (empty, singletons over `I`, `[1,1,1]`, small arrays with repeats, 10 random arrays of length
  4..=9 over `I`, an array of length 40, and `[i % 7 for i in range(2000)]`), each with the values `0, 1, 2, 6, MIN,
  MAX, -1, 7` used as `q` for `find_first` and as `t` for `all_below`.
  Example: `find_first([5,3,9,3], 3) == 1`, `find_first([5,3], 4) == -1`, `all_below([1,2], 3) == true`.

## q02 - tree traversal with size termination

Wrappers (both `! alloc`):

```pruv
fn node_count(a: [i64]) -> i64 ! alloc
  requires len(a) <= 1000
  ensures result == len(a)

fn empty_count(a: [i64]) -> i64 ! alloc
  requires len(a) <= 1000
  ensures result == len(a) + 1
```

- Define `enum Tree { Empty, Node(value: i64, left: Tree, right: Tree) }`. Each wrapper first builds a binary tree that
  holds the elements of `a` (one `Node` per element; any shape, e.g. balanced by splitting the index range in the middle)
  and then computes its result by a recursive walk over that tree: `node_count` counts the `Node`s, `empty_count` counts
  the `Empty` leaves. Neither wrapper may compute its result from `len(a)` directly.
- Required constructs: the `Tree` enum above, a function with `decreases size(t)` that `match`es on a `Tree`.
- Tests: arrays of length 0, 1, 2, 3, 7, 8, 40, 1000 and 10 random lengths `0..=100` (elements random over `I`).
  Example: `node_count([4,5,6]) == 3`, `empty_count([]) == 1`.

## q03 - bounded descent over a token array (cursor result)

Tokens: `0` = atom, `1` = open list, `2` = close list; any other number is invalid. A value is an atom, or an open token
followed by zero or more values and a close token. Wrappers (no effects):

```pruv
fn value_end(a: [i64], i: i64) -> i64
  requires 0 <= i && i <= len(a) && len(a) <= 1000
  ensures result == 0 - 1 || (i < result && result <= len(a))
  ensures (i < len(a) && a[i] == 0) ==> result == i + 1
  ensures (i == len(a) || (a[i] != 0 && a[i] != 1)) ==> result == 0 - 1

fn is_value(a: [i64]) -> bool
  requires len(a) <= 1000
  ensures result ==> len(a) >= 1
  ensures (len(a) == 1 && a[0] == 0) ==> result
  ensures (len(a) >= 1 && a[0] == 0 && len(a) != 1) ==> !result
```

- `value_end(a, i)`: if a value starts at position `i`, the position just after it; otherwise `-1` (also when the input
  ends before the value is complete or contains an invalid token inside it).
- `is_value(a)`: true exactly when the whole array is one value (`value_end(a, 0) == len(a)`).
- These contracts do not state the full meaning (the grammar is not expressible as a contract, SPEC 6e Limits); the
  grader checks the exact results.
- Required constructs: two functions that call each other (mutual recursion), each with a `decreases` clause.
- Tests: `value_end` on about 30 token arrays (`[]`, `[0]`, `[1,2]`, `[1,0,0,2]`, `[1,1,2,0,2]`, unbalanced and invalid
  ones such as `[2]`, `[1]`, `[1,0]`, `[1,3,2]`, `[0,0]`, 15 random arrays over `{0,1,2}` of length 1..=12, one nested
  list of depth 40 and one flat list of 500 atoms) at every start position `0..=len(a)`; `is_value` on the same arrays.
  Example: `value_end([1,0,1,2,2,0], 0) == 5`, `value_end([1,0,1,2,2,0], 5) == 6`, `value_end([1,0], 0) == -1`.

## q04 - nested buffer copies are independent

Wrappers (both `! alloc`):

```pruv
fn bumped_first(a: [i64], d: i64) -> i64 ! alloc
  requires 1 <= len(a) && len(a) <= 1000
  requires -1000000000 <= a[0] && a[0] <= 1000000000
  requires -1000000000 <= d && d <= 1000000000
  ensures result == 2 * a[0] + d

fn swapped_lengths(a: [i64], b: [i64]) -> i64 ! alloc
  requires len(a) <= 1000 && len(b) <= 1000
  ensures result == 1000 * len(b) + len(a)
```

- Define `struct Buf { data: [i64] }` and `struct Pair { left: Buf, right: Buf }`.
- `bumped_first`: build a `Pair` `p` whose two buffers are copies of `a`; copy `p` into a mutable `q`; add `d` to element
  0 of `q.left.data` (copy out, change, assign back); return `p.left.data[0] + q.left.data[0]`. The function must contain
  `assert p.left.data[0] == a[0];` after the change to `q` (the copy is independent).
- `swapped_lengths`: build a `Pair` `p` with `left` a copy of `a` and `right` a copy of `b`; copy it into a mutable `q`;
  swap `q.left` and `q.right`; return `1000 * len(q.left.data) + len(q.right.data)`. The function must contain
  `assert len(p.left.data) == len(a);` after the swap.
- Required constructs: the two structs above and the two `assert` lines.
- Tests: `bumped_first` on 20 arrays (lengths 1..=9 and one of 1000, first elements over `{-1000000000, -1, 0, 1, 7,
  1000000000}`) with `d` in `{-1000000000, -3, 0, 5, 1000000000}`; `swapped_lengths` on all pairs of arrays with lengths
  `{0, 1, 2, 9, 1000}`.
  Example: `bumped_first([4,9], 3) == 11`, `swapped_lengths([1,2,3], []) == 3`.
