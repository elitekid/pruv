# G6 problems (calling Rust, standard collections)

Each solution is one Pruv file `qNN.pruv`. The language rules are in SPEC.md (section 6d, Calling Rust and standard
collections; sections 6b and 6c for `str` and generics). Nothing else is needed.

Rules common to all four problems:

- Define the **public wrappers** with exactly the given names and types. Collection-bearing functions (any function whose
  parameters or result mention `Vec`, `HashMap` or `String`) are private to the Pruv program, so the grader only calls the
  wrappers; their types are `i64`, `bool`, `[i64]` and `str`. Helper functions are allowed.
- Use the collection named in each problem inside the wrapper (q01 `Vec<i64>`, q02 `HashMap<i64, i64>`, q03 `String`,
  q04 a `trusted rust fn`). The grader tests behaviour; `run.py` also rejects a file that never mentions the required
  catalog operations (see "Required constructs" under each problem).
- The file must verify (no `--no-verify`), on both compilers and on both backends, with the default `--foreign-checks`
  setting, and must not panic on the test inputs. Allocating functions are written `! alloc`.
- State the **full meaning** in `ensures`: the contract of every wrapper must determine the result completely (for the
  given inputs there is exactly one result that satisfies the `ensures`). A weaker contract such as `ensures true` or only
  a bound on the result is a failed attempt, even if the tests pass. Write `requires` exactly as listed below.
- The grader compares the wrapper's result (Rust `Debug` text) with a trusted reference computed in Python.

Type mapping at the wrapper boundary: `i64` is `i64`, `bool` is `bool`, `[i64]` is `&[i64]`, `str` parameters are `&str`
and `str` results are `String`.

Build configurations: the Python and the Rust compiler, each with the Rust backend and with the LLVM backend (four
configurations). On LLVM the generated bindings (which contain the Rust shim for collections and trusted functions) are
compiled by rustc together with the object files. All four must give the reference results.

Test inputs are generated by `tests()` in `run.py` (seeded). `I = {i64::MIN, -1, 0, 1, 2, 7, i64::MAX}` is the set of
"extreme" integers used in several generators.

## q01 - Vec filter and accumulate

Wrappers (both `! alloc`):

| wrapper | requires | meaning |
|---|---|---|
| `fn count_in_range(a: [i64], lo: i64, hi: i64) -> i64` | `len(a) <= 1000000` | the number of elements `x` of `a` with `lo <= x && x <= hi` |
| `fn running_total(a: [i64]) -> i64` | `len(a) <= 1000` and `forall k in 0..len(a): 0 <= a[k] && a[k] <= 1000` | the sum of all elements of `a` (0 for the empty array) |

- `count_in_range`: copy the elements inside `[lo, hi]` into a `Vec<i64>` while scanning `a`, and return the length of that
  `Vec`. `lo > hi` is allowed (then the result is 0). `ensures result == count(k in 0..len(a): lo <= a[k] && a[k] <= hi)`.
- `running_total`: build a `Vec<i64>` of the prefix sums (element `j` is `a[0] + .. + a[j]`) and return its last element
  (0 when `a` is empty). `ensures result == sum(k in 0..len(a): a[k])`.
- Required constructs: `vec_push`.
- Tests: `count_in_range` on about 20 arrays (empty, singletons including `i64::MIN`/`i64::MAX`, small 0/1 arrays,
  random arrays of length 4..=9 over `I` and small numbers, one array of length 40, one of length 120) each with 9
  ranges `(lo, hi)`: `(0,1) (-1,7) (2,2) (5,3) (MIN,MAX) (MIN,-1) (1,MAX) (7,7) (-5,5)`. `running_total` on the empty array,
  `[0]`, `[1000]`, `[1,2,3]`, 12 random arrays (elements `0..=1000`, length 1..=9), one of length 40, `[1000]*40` and
  `[1000]*1000`.
  Example: `count_in_range([5,3,9,-1,7,7,2], 3, 7) == 4`, `running_total([1,2,3]) == 6`.

## q02 - scalar-key histogram

Wrappers (both `! alloc`, both `requires len(a) <= 1000000`):

- `fn count_value(a: [i64], q: i64) -> i64`: build a histogram `HashMap<i64, i64>` (value -> number of occurrences) of all
  elements of `a`, then answer how often `q` occurs (0 if it does not). `ensures result == count(k in 0..len(a): a[k] == q)`.
- `fn seen(a: [i64], q: i64) -> bool`: true exactly when `q` occurs in `a`
  (`ensures result ==> count(k in 0..len(a): a[k] == q) > 0` and `ensures !result ==> count(k in 0..len(a): a[k] == q) == 0`).
  It may call `count_value`.
- Required constructs: `map_insert` and `map_get`.
- Tests: about 20 arrays (empty, `[0]`, `[1,1,1]`, `[MIN,MAX,MIN]`, small arrays with repeats, 10 random arrays of length
  4..=9 over `I` and 3, an array of length 40 over `{0,1,2,MAX}`, and `[i % 7 for i in range(2000)]`), each with
  the queries `0, 1, 2, 3, MIN, MAX, -1, 7`.
  Example: `count_value([2,2,1,2,0], 2) == 3`, `count_value([2,2,1,2,0], 5) == 0`.

## q03 - UTF-8 String assembly

Wrappers (both `! alloc`):

| wrapper | requires | meaning |
|---|---|---|
| `fn join_pair(a: str, b: str, sep: str) -> str` | `len(a) <= 1000 && len(b) <= 1000 && len(sep) <= 1000` | the bytes of `a`, then of `sep`, then of `b` |
| `fn joined_len3(a: str, b: str, c: str, sep: str) -> i64` | all four `len(..) <= 1000` | the byte length of `a ++ sep ++ b ++ sep ++ c` |

- Build the text in a `String` with `string_push_str` and hand it out with `string_to_str` (`join_pair`) or `len`
  (`joined_len3`). `len` of a `str` and of a `String` counts **bytes**, not characters.
- `join_pair`: `len(result) == len(a) + len(sep) + len(b)`, and the bytes of `result` are exactly `a`, `sep`, `b` in this
  order (state it with three `forall` clauses over the byte positions, e.g. `result[len(a) + k] == sep[k]`).
- `joined_len3`: `ensures result == len(a) + len(b) + len(c) + 2 * len(sep)`.
- Required constructs: `string_push_str` and `string_to_str`.
- Tests: `join_pair` for all pieces `a, b` in `["", "a", "é", "한글", "😀", "ab,c", "x\ny\0"]` and all separators in
  `["", ",", " — ", "→", "😀😀"]` (245 cases), `joined_len3` for 40 seeded triples of these pieces with these
  separators. Results are compared as the exact Rust string.
  Example: `join_pair("a", "b", ", ") == "a, b"`, `joined_len3("é", "", "x", ",") == 5`.

## q04 - external Rust parser adapter

The crate `adapter/g6q_adapter.rs` (compiled by the grader as an rlib named `g6q_adapter` and given to the compiler with
`--rust-extern g6q_adapter=PATH`) contains the Rust function

```rust
pub fn parse_digit(s: &str) -> i64
```

It returns the value `0..=9` of a text that is exactly one ASCII digit character, and `-1` for everything else (empty text,
two or more characters, a letter, whitespace, a non-ASCII digit such as `٣`). You do **not** write or change the adapter. You
write the declaration below (this contract is part of the problem, copy it exactly) and the wrappers that use it:

```pruv
trusted rust fn parse_digit(s: str) -> i64
  ensures result >= -1 && result <= 9
  ensures (len(s) == 1 && 48 <= s[0] && s[0] <= 57) ==> result == s[0] - 48
  ensures !(len(s) == 1 && 48 <= s[0] && s[0] <= 57) ==> result == -1
  = "::g6q_adapter::parse_digit";
```

Let `D(s)` stand for `len(s) == 1 && 48 <= s[0] && s[0] <= 57` ("s is exactly one ASCII digit"; byte 48 is `0`, 57 is `9`).
Contracts have no macros, so write it out each time. Wrappers (no effects, no `requires`; they call `parse_digit`):

| wrapper | meaning |
|---|---|
| `fn digit_or(s: str, d: i64) -> i64` | the digit value of `s` if `D(s)`, otherwise `d` |
| `fn is_digit(s: str) -> bool` | true exactly when `D(s)` |
| `fn add_digits(a: str, b: str) -> i64` | `a[0] + b[0] - 96` (the sum of the two digit values) if `D(a)` and `D(b)`, otherwise `-1` |

- Contracts: `digit_or`: `D(s) ==> result == s[0] - 48` and `!D(s) ==> result == d`. `is_digit`: `result ==> D(s)` and
  `!result ==> !D(s)`. `add_digits`: `(D(a) && D(b)) ==> result == a[0] + b[0] - 96` and `!(D(a) && D(b)) ==> result == -1`.
- Required constructs: the `trusted rust fn parse_digit` declaration with the path `"::g6q_adapter::parse_digit"`.
- Tests: `digit_or` for `s` in `["0","1","5","9","a","","12"," 5","5 ","/",":","-","٣","５","😀","00"]` and
  `d` in `{-7, 0, 100, MIN, MAX}`; `is_digit` for the same strings; `add_digits` for all pairs of
  `["0","9","5","a","","12","٣"]`.
  Example: `digit_or("7", 100) == 7`, `digit_or("x", 100) == 100`, `add_digits("4", "9") == 13`, `add_digits("4", "x") == -1`.
