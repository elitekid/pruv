# Pruv Node-API bridge (L1 first and second bundles, L2 first to eleventh bundles)

A native Node-API module that lets Node and Electron call verified Pruv
functions. The Rust in `gen/` is generated by the Pruv compiler from
`bench/l0/{clip_bytes,host_within,version_at_least,col_letters,term_plain,decode_bytes,zip_total,encode_png,split_text,group_text,image_shrink,number_ranges,clip_sheet,kind_of,row_pieces,sheet_chunks}.pruv`; do not edit it.
`decode_bytes` calls trusted encoding_rs adapters in `bench/l0/decode_adapter`
(crate `pruv_decode`, a path dependency of this crate).

Exports (`index.mjs`):

- `clipBytes(text, max)` — clip to at most `max` UTF-8 bytes on a character boundary.
- `hostWithin(host, site)` — 1:1 with the Pruv function, one site; the caller loops over sites.
- `versionAtLeast(a, b)` — exact three-component decimal comparison with ASCII whitespace trimming; malformed versions return false.
- `colLetters(col)` — bijective base-26 spreadsheet column name; zero returns an empty string.
- `decodeBytes(bytes)` → `{text, encoding}` — Lair's decodeBytes: UTF-8/UTF-16LE/UTF-16BE BOM, else strict UTF-8, else EUC-KR (`cp949`). Accepts a Uint8Array or Buffer.
- `looksBinary(bytes)` — a NUL byte in the first 8 KiB.
- `termPlain(state, data)` / `termState(state, data)` — streaming terminal-text cleaner (drops escape sequences and controls, folds CR/CRLF to LF). Start with state 0; pass `termState` of each chunk to the next chunk.
- `zipUncompressedTotal(bytes)` — sum of the uncompressed sizes in a zip central directory; null if unreadable, Infinity if zip64-shaped.
- `pngScanlines(data, width, height, kind, maxPixels)` → `{width, height, raw}` or null — the verified pixel part of Lair's encodePng (downsample, RGBA onto white, 1-bit inversion).
- `encodePng(image, maxPixels)` — Lair's encodePng: `pngScanlines` plus JS deflate and PNG chunks, byte-identical to TS.
- `splitText(text, max)` — Lair's page text splitter: pieces of at most `max` UTF-16 units, cut at a newline or space when possible, trimmed.
- `groupTexts(texts, max)` → `{from, to, text}[]` — Lair's groupNumbered: items gathered into pieces of at most `max` UTF-16 units, an oversized item split alone; 0-based item indexes.
- `chunkLines(lines, max)` / `chunkBlocks(blocks, max)` — Lair's chunkers (`{loc, text}`), built on `groupTexts`.
- `jpegOrientation(bytes)` — Lair's readOrientation: EXIF orientation 1..8 from the first APP1 Exif segment, 1 if none or malformed.
- `shrinkPixels(data, width, height, orientation)` → `{width, height, data}` or null — the pixel part of Lair's shrinkJpeg (box shrink to a 2000 long side, then the EXIF orientation); null where TS returns undefined.
- `shrinkJpeg(bytes, jpeg)` — Lair's shrinkJpeg with the jpeg-js module passed in; returns a Buffer or undefined.
- `numberRanges(numbers)` — Lair's page/line/block range text ("3-5, 8"), cut at a range boundary with ", …" past 400 characters.
- `clipSheetBackground()` / `clipSheetCell(sheet, index, data, width, height, outW, outH, label, number)` — the pixels of Lair's renderClipSheet: the blank 1560 × 920 RGBA board, and one cell (picture box-fitted and centred, label strip, number box) drawn onto a copy.
- `renderClipSheet(cells, jpeg)` — Lair's renderClipSheet with the jpeg-js module passed in; only the decode, the encode and the JS-rounded fit size are JS.
- `kindCode(name)` / `extensionAt(name)` — Lair's kindOf as a code (0 unknown, 1 pdf, 2 docx, 3 xlsx, 4 csv, 5 image, 6 text, 7 unsupported) and the UTF-16 index where extensionOf's text starts (-1 for none).
- `kindOf(name)` / `extensionOf(name)` — Lair's kindOf and extensionOf; only the Unicode lowercasing of the extension text is JS.
- `rowTextPieces(texts, rowNo, max)` → `{row, col1, col2, text}[]` — Lair's rowPieces on cell texts: "행 N: " and the non-empty cells joined with " | ", gaps labelled with column letters, each piece at most `max` UTF-16 units after the head.
- `rowPieces(row, rowNo, max)` — Lair's rowPieces on raw cell values; only cellText (the value-to-text step) is JS.
- `cellRange(row1, row2, col1, col2)` → string — Lair's rangeOf: `"A1"` for a single cell, else `"A1:C9"`.
- `sheetChunks(name, pieces, max)` → `{range, row1, row2, col1, col2, text}[]` — Lair's extractSheets grouping: pieces join the open chunk until the size (header `"[시트: name]\n"` plus each piece and a newline, in UTF-16 units) would pass `max` or the row is more than 50 rows after the last one.
- `extractSheetChunks(name, rows, max)` — rowPieces on every row, then sheetChunks, as Lair's chunk objects `{loc: {kind: 'cells', sheet, range, row1, row2, col1, col2}, text}`. The cell and character limits of extractSheets stay with the caller.
- `textAroundPlan(bytes, line, before, after, maxBytes)` → number[] — the verified Pruv plan of Lair textAround over the bytes of a whole file: `[0, totalLines]` when the first shown line (`max(1, line - before)`) is past the end, else `[1, totalLines, shownTarget, beforeStart, beforeEnd, targetStart, targetEnd, afterStart, afterEnd, newlinesBefore, truncated, targetCut]`, the shown bytes being the three slices in order.
- `textAround(request)` (async) — Lair's textAround result for `{path, line, before?, after?, maxBytes?, expectSource?}` (defaults 200, 200, 256 KiB, line floored and at least 1, failure records with the same `reasonI18n` keys). Unlike Lair it reads the whole file into memory instead of 1 MiB blocks; the byte choice is textAroundPlan, the decode is decodeBytes. After Lair's defaults, before/after/maxBytes outside the textAroundPlan domain throw InvalidArg.
- `parseHtmlRecords(html)` → number[] — the verified Pruv record list of Lair parseHtml (docx.ts) in document order: a text node is `[0, parent, n, code points...]`, an element `[1, parent, n, lowercase tag code points..., then for href, colspan and rowspan either -1 or m and the m decoded value code points]`; parent is the element number (creation order from 0) or -1 for the top level, and blank top-level text is already dropped.
- `docxPartsRecords(html)` → number[] — `[len(rec), the parseHtmlRecords list, the <img\b count, then nblocks, per block (kind 0 p / 1 h / 2 li / 3 tr, element number, n, text code points), hlen, preview HTML code points]`: the verified Pruv walk of Lair docxParts after its parse.
- `docxParts(html)` — Lair's `{blocks: [{n, kind, el, text}], html, images}` from docxPartsRecords; `el` is the El object (as parseHtml builds it) of the block's element.
- `parseHtml(html)` — Lair's El tree `{tag, attrs, children}` built from parseHtmlRecords; `attrs` holds only href, colspan and rowspan, the attributes Lair's DOCX code reads. Lone surrogates in the string reach Pruv as U+FFFD.

## Regenerate

```
python bridge/node/regen.py          # overwrite gen/*.rs
python bridge/node/regen.py --check  # exit 1 if gen/*.rs is stale
```

Needs both compilers and Python with `z3-solver`. `PRUV_PYTHON` and `PRUVC_RS`
select installed tools (including read-only tools in a main checkout).
Regeneration verifies with both compilers and requires byte-identical Rust output
for all fifteen generated files. `decode_bytes` is compiled against the adapter rlib,
which regen builds first (`cargo build --locked` under `bench/l0/work/decode-adapter`). Temporary output stays under `bench/l0/work`.
If verification fails the
compiler's exit code is returned and the bridge must not be built.

## Build and test

```
node bridge/node/build.mjs   # cargo build --release, copies to bridge/node/pruv_bridge.node
node bridge/node/test.mjs [--cases N] [--seed S]
```

`CARGO_TARGET_DIR` is respected. The test compares the native functions with
independent JS oracles (must be 0 mismatches) and reports, informationally,
how often the verbatim Lair TS originals differ.

## `requires` → exception

The generated code panics when its `requires` is violated. The wrapper checks
first and throws a JS `Error` (`InvalidArg`) instead:

| Call | Condition | Message |
| --- | --- | --- |
| `clipBytes` | `max` outside 0..=1000000 | `clipBytes: max must be in 0..=1000000` |
| `clipBytes` | text > 1000000 UTF-8 bytes | `clipBytes: text must be at most 1000000 UTF-8 bytes` |
| `hostWithin` | host or site > 4096 UTF-8 bytes | `hostWithin: host and site must be at most 4096 UTF-8 bytes each` |
| `versionAtLeast` | a or b > 4096 UTF-8 bytes | `versionAtLeast: a and b must be at most 4096 UTF-8 bytes each` |
| `colLetters` | nonfinite, fractional, negative or > 1e15 number | `colLetters: col must be an integer in 0..=1000000000000000` |
| `termPlain` / `termState` | state not an integer in 0..=11 | `termPlain: state must be an integer in 0..=11` (or `termState: ...`) |
| `decodeBytes` / `looksBinary` | more than 1e12 bytes | `decodeBytes: data must be at most 1000000000000 bytes` (or `looksBinary: ...`) |
| `pngScanlines` / `encodePng` | width, height not integers in 1..=2^40, width × height > 2^40, kind not 1..=3, maxPixels not an integer in 1..=2^36 | `pngScanlines: width must be an integer in 1..=1099511627776` (and similar) |
| `splitText` | max not an integer in 2..=2^40, or text > 5e11 UTF-8 bytes | `splitText: max must be an integer in 2..=1099511627776` (or `splitText: text must be ...`) |
| `jpegOrientation` | more than 2^40 bytes | `jpegOrientation: data must be at most 1099511627776 bytes` |
| `shrinkPixels` / `shrinkJpeg` | width, height not integers in 1..=65535, orientation not 1..=8, data not 4 × width × height bytes | `shrinkPixels: width must be an integer in 1..=65535` (and similar) |
| `groupTexts` / `chunkLines` / `chunkBlocks` | max not an integer in 2..=2^40, or texts joined with newlines > 2.5e11 UTF-8 bytes | `groupTexts: max must be an integer in 2..=1099511627776` (or `groupTexts: texts joined ...`) |
| `numberRanges` | an element nonfinite, fractional or outside -1e15..=1e15 | `numberRanges: numbers must be integers in -1000000000000000..=1000000000000000` |
| `clipSheetCell` / `renderClipSheet` | sheet not 5740800 bytes, index not 0..=3, width/height not integers in 1..=65535, outW not 1..=768, outH not 1..=432, data not 4 × width × height bytes, label > 1000000 or number > 4096 UTF-8 bytes | `clipSheetCell: width must be an integer in 1..=65535` (and similar) |
| `kindCode` / `extensionAt` / `kindOf` / `extensionOf` | name > 1e12 UTF-8 bytes | `kindCode: name must be at most 1000000000000 UTF-8 bytes` (or `extensionAt: ...`) |
| `cellRange` | a row or column not an integer in 1..=1e15 | `cellRange: row1 must be an integer in 1..=1000000000000000` (and similar) |
| `sheetChunks` | max not an integer in 1..=2^40, a header longer than 2^40, more than 1e11 pieces, or a piece row/column not an integer in 1..=1e15 | `sheetChunks: max must be an integer in 1..=1099511627776` (and similar) |
| `textAroundPlan` / `textAround` | line not an integer in 1..=1e15, before/after not integers in 0..=1e15, maxBytes not an integer in 0..=2^40, bytes not a Uint8Array/Buffer or longer than 2^40 | `textAroundPlan: line must be an integer in 1..=1000000000000000` (and similar) |
| `parseHtmlRecords` / `parseHtml` / `docxPartsRecords` / `docxParts` | html not a string or longer than 2^38 UTF-8 bytes | `parseHtmlRecords: html must be at most 274877906944 UTF-8 bytes` |
| `rowTextPieces` / `rowPieces` | rowNo not an integer in 1..=1e15, max not an integer in 1..=2^40, or texts joined with newlines > 1.8e11 UTF-8 bytes | `rowTextPieces: rowNo must be an integer in 1..=1000000000000000` (and similar) |

The `colLetters` wrapper accepts an f64 so fractional inputs are rejected before
integer conversion. Wrong JS types raise Node-API type errors (`NumberExpected`
or `StringExpected`); numeric/domain precondition violations raise `InvalidArg`.

Version tests use an independent BigInt oracle; column tests use a BigInt
length-block oracle, dense 0..100000 and power-of-26 boundary cases. TS counts
are informational; the termPlain TS differences all come from lone surrogates (TS drops them, Node-API turns them into U+FFFD). The textAround TS differences are all in `text` (every other field matches; a field difference fails the test): this Node's TextDecoder decodes the EUC-KR and invalid bytes there differently from decodeBytes, the same cause as the decodeBytes TS count; in Lair's Electron the bench runner `run_text_around.py` finds no difference. All error checks passed. `node build.mjs`, `node test.mjs`
and `python3 regen.py --check` exited 0 (commands run from this directory or
with the equivalent repository-relative paths). An initial test expected
InvalidArg for wrong JS types; correcting that expectation resolved the failure.
See `bench/l0/README.md` for exact proved contracts and four-way cross-check counts.

## Recorded decodeBytes validation (L2 second bundle)

macOS arm64, Node v26.4.0, seed 12345: 21,939 byte strings (1,939 edge cases)
from `bench/l0/decode_oracle.py`, an independent WHATWG decoder that reads the
official EUC-KR index. Native/oracle mismatches 0 for `[text, encoding, binary]`.
TS/oracle differences 6,571, all from Homebrew Node 26's `TextDecoder('euc-kr')`
(byte 0x80 decodes to U+0080 instead of U+FFFD). Lair runs decode.ts in Electron,
whose Node 24.22.2 / ICU 78.2 matches WHATWG: `bench/l0/run_decode_bytes.py`
runs the TS copy there and gets 21,939/21,939. The test needs `python3`
(`python` on Windows, or `PYTHON`) to produce the oracle cases.

Loading the addon into the installed Lair Preview (`ELECTRON_RUN_AS_NODE=1`)
fails on macOS with "mapping process and mapped file (non-platform) have different
Team IDs": Lair's hardened runtime has library validation, so a bridge shipped
with Lair must be signed with Lair's own signing identity.

## UTF-16 → UTF-8

JS strings are UTF-16; Node-API converts them to UTF-8, and lone surrogates
become U+FFFD. All byte limits count UTF-8 bytes.

## CI

`.github/workflows/node-bridge.yml` regenerates with `--check` on Ubuntu, then
builds and tests on macOS (arm64 and Intel), Windows and Linux. It runs only on
manual dispatch and on pushes to `main` touching `bridge/node/**`,
`bench/l0/*.pruv`, the decode adapter, oracle, TS copy and index, or the workflow itself.
