# Pruv Node-API bridge (L1 first and second bundles, L2 first to eleventh bundles)

A native Node-API module that lets Node and Electron call verified Pruv
functions. The Rust in `gen/` is generated by the Pruv compiler from
`bench/l0/{clip_bytes,host_within,version_at_least,col_letters,term_plain,decode_bytes,zip_total,encode_png,split_text,group_text,image_shrink,number_ranges,clip_sheet,kind_of,row_pieces,sheet_chunks,doc_labels,image_counts,join_ranges,cut_cell,sheet_range,page_ranges,grouped_number,under_root,cap_keep,evict_stop,index_terms,note_pairs,cell_date,cell_str,cell_int,extract_version,chunk_page,text_lines,luhn}.pruv`; do not edit it.
`decode_bytes` calls trusted encoding_rs adapters in `bench/l0/decode_adapter`
(crate `pruv_decode`, a path dependency of this crate).

Exports (`index.mjs`):

- `clipBytes(text, max)` — clip to at most `max` UTF-8 bytes on a character boundary.
- `hostWithin(host, site)` — 1:1 with the Pruv function, one site; the caller loops over sites.
- `versionAtLeast(a, b)` — exact three-component decimal comparison with ASCII whitespace trimming; malformed versions return false.
- `colLetters(col)` — bijective base-26 spreadsheet column name; zero returns an empty string.
- `decodeBytes(bytes)` → `{text, encoding}` — Lair's decodeBytes: UTF-8/UTF-16LE/UTF-16BE BOM, else strict UTF-8, else EUC-KR (`cp949`). Accepts a Uint8Array or Buffer.
- `looksBinary(bytes)` — a NUL byte in the first 8 KiB.
- `termPlain(state, data)` / `termState(state, data)` — streaming terminal-text cleaner (drops escape sequences and controls, folds CR/CRLF to LF). Start with state 0; pass `termState` of each chunk to the next chunk.
- `zipUncompressedTotal(bytes)` — sum of the uncompressed sizes in a zip central directory; null if unreadable, Infinity if zip64-shaped.
- `pngScanlines(data, width, height, kind, maxPixels)` → `{width, height, raw}` or null — the verified pixel part of Lair's encodePng (downsample, RGBA onto white, 1-bit inversion).
- `encodePng(image, maxPixels)` — Lair's encodePng: `pngScanlines` plus JS deflate and PNG chunks, byte-identical to TS.
- `splitText(text, max)` — Lair's page text splitter: pieces of at most `max` UTF-16 units, cut at a newline or space when possible, trimmed.
- `groupTexts(texts, max)` → `{from, to, text}[]` — Lair's groupNumbered: items gathered into pieces of at most `max` UTF-16 units, an oversized item split alone; 0-based item indexes.
- `chunkLines(lines, max)` / `chunkBlocks(blocks, max)` — Lair's chunkers (`{loc, text}`), built on `groupTexts`.
- `jpegOrientation(bytes)` — Lair's readOrientation: EXIF orientation 1..8 from the first APP1 Exif segment, 1 if none or malformed.
- `shrinkPixels(data, width, height, orientation)` → `{width, height, data}` or null — the pixel part of Lair's shrinkJpeg (box shrink to a 2000 long side, then the EXIF orientation); null where TS returns undefined.
- `shrinkJpeg(bytes, jpeg)` — Lair's shrinkJpeg with the jpeg-js module passed in; returns a Buffer or undefined.
- `numberRanges(numbers)` — Lair's page/line/block range text ("3-5, 8"), cut at a range boundary with ", …" past 400 characters.
- `csvName(name)` — Lair's csvName: the part of a file name after the last `/` or `\`, without the extension after its last `.` (kept if that dot is the last character), `"표"` if nothing is left. Lone surrogates reach Pruv as U+FFFD.
- `countListText(pages, counts, max)` / `countListMore(n, max)` — the verified parts of Lair's countList: the first `max` items as "3 (2), 5 (1)", and `max(0, n - max)`.
- `countList(items, max = 20)` — Lair's `{list, more}` from `countListText` and `countListMore`.
- `imageCountText(pages, counts)` / `imageCounts(items)` — the Korean image count list of Lair's extractPdf (`listOf` in pdf.ts): the first 20 items as "3쪽 2개, 5쪽 1개" and " 외 N쪽" for the rest.
- `textLineCounts(text, chars)` / `textLines(text, chars)` — the line part of Lair's textDraft (extract.ts): `{lines, keep}`, the line count after splitting on LF (one trailing CR dropped per line, an empty last line dropped) and how many leading lines fit `chars` (running total of UTF-16 length + 1). Lone surrogates reach Pruv as U+FFFD (still one unit).
- `luhn(text)` — Lair's luhn (common-memory.ts), the card number check of sensitiveReason: the Luhn sum over the UTF-16 units of `text`, right to left, every second `unit - 48` doubled (9 taken off when over 9), true on a multiple of 10. Lone surrogates reach Pruv as U+FFFD, so their unit value differs from the original's.
- `joinRangeParts(parts)` — Lair's joinRangeParts: the strings joined with `", "`; past 400 UTF-16 units cut at a part boundary (no separator while the kept text is still empty) and followed by `", …"`. The result is proved at most 1200 UTF-8 bytes. Lone surrogates reach Pruv as U+FFFD (still one unit).
- `cutCell(text)` — the cell cut in Lair's sheetWindow: a text longer than 200 UTF-16 units becomes its first 200 units followed by `"…"`; shorter texts come back unchanged. When unit 200 is the first half of a surrogate pair the result has U+FFFD there (TS keeps a lone high surrogate, which is U+FFFD once encoded as UTF-8). The result is proved at most 606 UTF-8 bytes.
- `sheetRange(totalRows, totalCols, request = {})` — the window arithmetic of Lair's sheetWindow: `[row, col, rowCount, colCount]` for request `{row, col, rows, cols}` (absent or null fields take 1, 1, 200, 50; start at least 1, wanted counts clamped to 1..500 rows / 1..100 columns, then cut to the sheet). The window is proved inside the sheet.
- `pageRanges(pages)` — Lair's rangeText from pdf.ts: page numbers as `"3~5쪽, 8쪽"` (a run of consecutive numbers becomes `first~last쪽`), joined with `", "`, no length cap. The result is proved at most 40 UTF-8 bytes per number.
- `groupedNumber(value)` — Lair's groupedNumber from context.ts: an integer as `toLocaleString('en-US')`, a `,` between groups of three digits (`"-1,234,567"`). The result is proved at most 33 bytes (the longest is 22).
- `under(path, root)` — Lair's under from archive.ts: `path === root`, or `path` starts with `root` followed by this platform's separator (`/`, or `\` on Windows; just `root` when it already ends with one). The result is proved equal to that byte predicate. Lone surrogates arrive as U+FFFD.
- `capKeep(lens, max)` — the cut of Lair's capChars from extract.ts: how many chunks stay when their character counts are added from the front and the first chunk whose running total goes over `max` is dropped with everything after it. The result is proved to keep a prefix whose total is within `max` while one more chunk would go over.
- `evictStop(bytes, free, limit)` — the choice Lair's evict makes in archive.ts: over the stored versions oldest first (`bytes` in that order, `free[k]` = `bytes[k]` when version k may be deleted, 0 when it is pinned or kept), the index where the walk stops because the total left is within `limit`; evict deletes the deletable versions before it. The result is proved to be the first such index, or the length when there is none.
- `indexTerms(tok, vocab)` — the integer part of Lair's buildIndex in search.ts for one chunk: `tok` holds the chunk's token ids (the host numbers the token strings, `0 <= id < vocab`); the result is `[m, id_1, count_1, ..., id_m, count_m]`, the distinct ids in order of first appearance (the order of buildIndex's tf Map) with their counts. Proved: the shape, every id is a token of the chunk, ids are pairwise distinct, every count is in `1..=tok.length`; exact counts and order are checked against the oracle.
- `notePairs(n0, has, pre, keys)` — the key list Lair's addNote / addMissing in context.ts (with their helper padded) keep beside a draft list: `n0` texts are already in the list, `has` is 1 when the key list exists with entries `pre` (0 = null, k = key k, the host numbers the keys), and `keys[j]` is the key of call j (0 = none). The result is `[0]` when the key list stays absent, else `[1, entries...]`. Proved entry by entry: absent exactly when there was no list and no call carried a key; with no calls the old entries as they are; otherwise the old entries, nulls up to the old text count, then every call's key.
- `cellDate(ms)` — the Date branch of Lair's cellText in sheets.ts: a spreadsheet date cell as `"YYYY-MM-DD"` from the UTC calendar fields (the year unpadded, so `"-5"` or `"275760"`), plus `" HH:MM"` when the UTC hour, minute or second is nonzero. `ms` is the Date's time value (`date.getTime()`), any valid Date. The result is proved at most 35 bytes (the longest is 19).
- `cellStr(text)` — the string branch of Lair's cellText in sheets.ts: `text.replace(/\r?\n/g, ' ').trim()`. Every `"\r\n"` and `"\n"` becomes one space (a lone `"\r"` stays), then the ECMAScript trim white space (U+0009..U+000D, U+0020, U+00A0, U+1680, U+2000..U+200A, U+2028, U+2029, U+202F, U+205F, U+3000, U+FEFF) is cut from both ends. The result is proved no longer than the input in UTF-8 bytes.
- `cellInt(n)` — the number branch of Lair's cellText in sheets.ts on safe integers: `String(Number(n.toPrecision(15)))`. An integer of at most 15 digits prints unchanged; a 16-digit one is rounded to 15 significant digits, ties away from zero (`9007199254740991` gives `"9007199254740990"`). The result is proved at most 17 bytes.
- `sha256Hex(text)` — Lair's `sha256` in versions.ts on a string: SHA-256 of the UTF-8 bytes as 64 lowercase hex digits, written out in Pruv with integer arithmetic (Pruv has no bit operators). The result is proved to be 64 bytes.
- `extractVersionOf(sourceVersion, kind, variant = '')` — Lair's extraction version key in versions.ts: `sha256Hex` of the three parts and the fixed `EXTRACTOR_VERSION` text joined by newlines.
- `chunkPage(page, text, max, ocr)` / `chunkImage(text, max, ocr)` — Lair's PDF page and OCR image chunkers in chunker.ts: the `splitText` pieces as `{ loc: { kind: 'page', page }, text, ocr? }` or `{ loc: { kind: 'image' }, text, ocr? }` drafts, `ocr` attached when truthy. Pruv's chunk_page returns `[page, start, end]` records and proves every record carries the page.
- `clipSheetBackground()` / `clipSheetCell(sheet, index, data, width, height, outW, outH, label, number)` — the pixels of Lair's renderClipSheet: the blank 1560 × 920 RGBA board, and one cell (picture box-fitted and centred, label strip, number box) drawn onto a copy.
- `renderClipSheet(cells, jpeg)` — Lair's renderClipSheet with the jpeg-js module passed in; only the decode, the encode and the JS-rounded fit size are JS.
- `kindCode(name)` / `extensionAt(name)` — Lair's kindOf as a code (0 unknown, 1 pdf, 2 docx, 3 xlsx, 4 csv, 5 image, 6 text, 7 unsupported) and the UTF-16 index where extensionOf's text starts (-1 for none).
- `kindOf(name)` / `extensionOf(name)` — Lair's kindOf and extensionOf; only the Unicode lowercasing of the extension text is JS.
- `rowTextPieces(texts, rowNo, max)` → `{row, col1, col2, text}[]` — Lair's rowPieces on cell texts: "행 N: " and the non-empty cells joined with " | ", gaps labelled with column letters, each piece at most `max` UTF-16 units after the head.
- `rowPieces(row, rowNo, max)` — Lair's rowPieces on raw cell values; only cellText (the value-to-text step) is JS.
- `cellRange(row1, row2, col1, col2)` → string — Lair's rangeOf: `"A1"` for a single cell, else `"A1:C9"`.
- `sheetChunks(name, pieces, max)` → `{range, row1, row2, col1, col2, text}[]` — Lair's extractSheets grouping: pieces join the open chunk until the size (header `"[시트: name]\n"` plus each piece and a newline, in UTF-16 units) would pass `max` or the row is more than 50 rows after the last one.
- `extractSheetChunks(name, rows, max)` — rowPieces on every row, then sheetChunks, as Lair's chunk objects `{loc: {kind: 'cells', sheet, range, row1, row2, col1, col2}, text}`. The cell and character limits of extractSheets stay with the caller.
- `textAroundPlan(bytes, line, before, after, maxBytes)` → number[] — the verified Pruv plan of Lair textAround over the bytes of a whole file: `[0, totalLines]` when the first shown line (`max(1, line - before)`) is past the end, else `[1, totalLines, shownTarget, beforeStart, beforeEnd, targetStart, targetEnd, afterStart, afterEnd, newlinesBefore, truncated, targetCut]`, the shown bytes being the three slices in order.
- `textAround(request)` (async) — Lair's textAround result for `{path, line, before?, after?, maxBytes?, expectSource?}` (defaults 200, 200, 256 KiB, line floored and at least 1, failure records with the same `reasonI18n` keys). Unlike Lair it reads the whole file into memory instead of 1 MiB blocks; the byte choice is textAroundPlan, the decode is decodeBytes. After Lair's defaults, before/after/maxBytes outside the textAroundPlan domain throw InvalidArg.
- `parseHtmlRecords(html)` → number[] — the verified Pruv record list of Lair parseHtml (docx.ts) in document order: a text node is `[0, parent, n, code points...]`, an element `[1, parent, n, lowercase tag code points..., then for href, colspan and rowspan either -1 or m and the m decoded value code points]`; parent is the element number (creation order from 0) or -1 for the top level, and blank top-level text is already dropped.
- `docxPartsRecords(html)` → number[] — `[len(rec), the parseHtmlRecords list, the <img\b count, then nblocks, per block (kind 0 p / 1 h / 2 li / 3 tr, element number, n, text code points), hlen, preview HTML code points]`: the verified Pruv walk of Lair docxParts after its parse.
- `docxParts(html)` — Lair's `{blocks: [{n, kind, el, text}], html, images}` from docxPartsRecords; `el` is the El object (as parseHtml builds it) of the block's element.
- `parseHtml(html)` — Lair's El tree `{tag, attrs, children}` built from parseHtmlRecords; `attrs` holds only href, colspan and rowspan, the attributes Lair's DOCX code reads. Lone surrogates in the string reach Pruv as U+FFFD.
- `tokenizeRecords(text)` → number[] — the verified Pruv tokenize of Lair search.ts (Unicode 17.0 lowercase with Final_Sigma, `[\p{L}\p{N}]+` words, CJK runs as the whole run when 3..=8 characters plus every two-character pair): `[count, per token: n, code points]`.
- `tokenize(text)` — Lair's token string array from tokenizeRecords. Lone surrogates reach Pruv as U+FFFD.

## Regenerate

```
python bridge/node/regen.py          # overwrite gen/*.rs
python bridge/node/regen.py --check  # exit 1 if gen/*.rs is stale
```

Needs both compilers and Python with `z3-solver`. `PRUV_PYTHON` and `PRUVC_RS`
select installed tools (including read-only tools in a main checkout).
Regeneration verifies with both compilers and requires byte-identical Rust output
for all fifteen generated files. `decode_bytes` is compiled against the adapter rlib,
which regen builds first (`cargo build --locked` under `bench/l0/work/decode-adapter`). Temporary output stays under `bench/l0/work`.
If verification fails the
compiler's exit code is returned and the bridge must not be built.

## Build and test

```
node bridge/node/build.mjs   # cargo build --release, copies to bridge/node/pruv_bridge.node
node bridge/node/test.mjs [--cases N] [--seed S]
```

`CARGO_TARGET_DIR` is respected. The test compares the native functions with
independent JS oracles (must be 0 mismatches) and reports, informationally,
how often the verbatim Lair TS originals differ.

integer conversion. Wrong JS types raise Node-API type errors (`NumberExpected`
or `StringExpected`); numeric/domain precondition violations raise `InvalidArg`.

## UTF-16 → UTF-8

JS strings are UTF-16; Node-API converts them to UTF-8, and lone surrogates
become U+FFFD. All byte limits count UTF-8 bytes.
