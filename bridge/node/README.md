# Pruv Node-API bridge (L1 first and second bundles, L2 first bundle)

A native Node-API module that lets Node and Electron call verified Pruv
functions. The Rust in `gen/` is generated by the Pruv compiler from
`bench/l0/{clip_bytes,host_within,version_at_least,col_letters,term_plain}.pruv`; do not edit it.

Exports (`index.mjs`):

- `clipBytes(text, max)` — clip to at most `max` UTF-8 bytes on a character boundary.
- `hostWithin(host, site)` — 1:1 with the Pruv function, one site; the caller loops over sites.
- `versionAtLeast(a, b)` — exact three-component decimal comparison with ASCII whitespace trimming; malformed versions return false.
- `colLetters(col)` — bijective base-26 spreadsheet column name; zero returns an empty string.
- `termPlain(state, data)` / `termState(state, data)` — streaming terminal-text cleaner (drops escape sequences and controls, folds CR/CRLF to LF). Start with state 0; pass `termState` of each chunk to the next chunk.

## Regenerate

```
python bridge/node/regen.py          # overwrite gen/*.rs
python bridge/node/regen.py --check  # exit 1 if gen/*.rs is stale
```

Needs both compilers and Python with `z3-solver`. `PRUV_PYTHON` and `PRUVC_RS`
select installed tools (including read-only tools in a main checkout).
Regeneration verifies with both compilers and requires byte-identical Rust output
for all five generated files. Temporary output stays under `bench/l0/work`.
If verification fails the
compiler's exit code is returned and the bridge must not be built.

## Build and test

```
node bridge/node/build.mjs   # cargo build --release, copies to bridge/node/pruv_bridge.node
node bridge/node/test.mjs [--cases N] [--seed S]
```

`CARGO_TARGET_DIR` is respected. The test compares the native functions with
independent JS oracles (must be 0 mismatches) and reports, informationally,
how often the verbatim Lair TS originals differ.

## `requires` → exception

The generated code panics when its `requires` is violated. The wrapper checks
first and throws a JS `Error` (`InvalidArg`) instead:

| Call | Condition | Message |
| --- | --- | --- |
| `clipBytes` | `max` outside 0..=1000000 | `clipBytes: max must be in 0..=1000000` |
| `clipBytes` | text > 1000000 UTF-8 bytes | `clipBytes: text must be at most 1000000 UTF-8 bytes` |
| `hostWithin` | host or site > 4096 UTF-8 bytes | `hostWithin: host and site must be at most 4096 UTF-8 bytes each` |
| `versionAtLeast` | a or b > 4096 UTF-8 bytes | `versionAtLeast: a and b must be at most 4096 UTF-8 bytes each` |
| `colLetters` | nonfinite, fractional, negative or > 1e15 number | `colLetters: col must be an integer in 0..=1000000000000000` |
| `termPlain` / `termState` | state not an integer in 0..=11 | `termPlain: state must be an integer in 0..=11` (or `termState: ...`) |

The `colLetters` wrapper accepts an f64 so fractional inputs are rejected before
integer conversion. Wrong JS types raise Node-API type errors (`NumberExpected`
or `StringExpected`); numeric/domain precondition violations raise `InvalidArg`.

## Recorded second-bundle validation

macOS arm64, Node v26.4.0, seed 12345, default 20,000 random cases:

| Function | Cases | Native/oracle mismatches | TS/oracle differences |
| --- | ---: | ---: | ---: |
| clipBytes | 20,000 | 0 | 8,555 |
| hostWithin | 20,000 | 0 | 308 |
| versionAtLeast | 20,139 | 0 | 3,580 |
| colLetters | 120,073 | 0 | 0 |
| termPlain + termState | 20,000 | 0 | 4,741 |

Version tests use an independent BigInt oracle; column tests use a BigInt
length-block oracle, dense 0..100000 and power-of-26 boundary cases. TS counts
are informational; the termPlain TS differences all come from lone surrogates (TS drops them, Node-API turns them into U+FFFD). All error checks passed. `node build.mjs`, `node test.mjs`
and `python3 regen.py --check` exited 0 (commands run from this directory or
with the equivalent repository-relative paths). An initial test expected
InvalidArg for wrong JS types; correcting that expectation resolved the failure.
See `bench/l0/README.md` for exact proved contracts and four-way cross-check counts.

## UTF-16 → UTF-8

JS strings are UTF-16; Node-API converts them to UTF-8, and lone surrogates
become U+FFFD. All byte limits count UTF-8 bytes.

## CI

`.github/workflows/node-bridge.yml` regenerates with `--check` on Ubuntu, then
builds and tests on macOS (arm64 and Intel), Windows and Linux. It runs only on
manual dispatch and on pushes to `main` touching `bridge/node/**`,
`bench/l0/*.pruv` or the workflow itself.
